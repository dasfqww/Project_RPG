# 공격에 따른 자동 무기 장착·수납

플레이어의 Equip/Unequip 입력 바인딩과 수동 stance 능력 활성화를 제거한다.
기존 에셋의 Equip spec은 로드아웃 부여 레벨을 읽는 호환 자료로만 남긴다.
가방의 영속 장비 장착/해제 명령은 이 전투 중 무기 휴대 동작과 별개다.

`URPGPlayerWeaponLoadoutComponent`가 선택된 무기의 입력 매핑·애니메이션 레이어·공격
능력을 등에 수납한 상태에서도 유지한다. 기존 시작 대검과 native 장비 모두 적용한다.
native 활성 세트/영속 장비 기록을 수납만으로 변경하거나 능력치를 회수하지 않는다.

- 초기 휴대 위치는 `WeaponBackSocket`이다.
- GAS가 공격을 활성화하면 공격 그래프보다 먼저 `WeaponHandSocket`에 부착한다.
  실제 공격 몽타주와 콤보의 다음 구간 실행도 마지막 공격 시각을 갱신한다.
- 마지막 공격부터 10초 뒤 기존 `AM_GreatSword_Equip`의 `Unequip` 구간을 재생한다.
  긴 홀딩/시전·다른 몽타주/피격 제어 중이면 끝날 때까지 수납을 미룬다.
- 기존 `Player.Event.Unequip.GreatSword` notify에서 등에 부착한다. notify가 누락되면
  정상 몽타주 종료 시 부착하며, 애니메이션을 재생할 수 없는 환경에서는 바로 수납한다.
- 수납 도중 공격하면 수납 몽타주를 중단하고 즉시 손에 부착한다. 늦게 도착한 수납
  이벤트는 Drawn 상태에서 무시한다. 사망/권한 회수 뒤에는 타이머가 수납을 시작하지 않는다.

타이머와 수납 결정은 서버 소유다. 공개 복제는 기존 무기 참조와 휴대 상태만 사용하며
개인 아이템 ID/스탯은 추가 공개하지 않는다. 클라이언트는 승인된 로컬 공격의 손 부착을
즉시 표현하고, 서버 휴대 상태로 수납 몽타주를 표현한다. 새로운 Tick은 없다.

2026-11-03 검증: 제품 7파일과 직접 회귀 2파일을 반영했다. 기존 정상 빌드 뒤 최신
변경 CPP의 집중 컴파일/링크 모듈(46B04A26…)에서 기존 로드아웃 4검사는 성공했다.
새 검사는 모형 소켓의 BoneName 누락으로 부착 기대만 실패했고, 시험 한 줄만 보완해
제품 객체를 유지한 사설 모듈(4D920782…)에서 새 자동 수납 검사 1개가 오류 없이 성공했다.
동일 최종 DLL에서 5개를 모두 재실행한 결과는 아니다. 정상 빌드의 동시 PCH 충돌 실패와
복구 재링크의 디버그 정보 경고는 보존했으며 전체 최신 UBT 성공으로 보고하지 않는다.

첫 공격/재공격의 손 부착, 10초 미만 유지·재설정·만료, 긴 공격 중 보류/종료 후 수납,
notify 수납, 수납 중 재공격·늦은 notify 무시, 사망·해제 수명과 능력 유지가 검사 범위다.
원본 몽타주의 `Equip`/`Unequip` 구간, Blueprint `AN_SendGameplayEvent`의 정확한 태그와
BP_Player의 두 소켓도 별도 Cmd에서 읽기만 하여 확인했다. Unequip 시작 1.666667초와
수납 이벤트 2.249809초의 차이는 약 0.583초다. 원본 애니메이션/Blueprint는 저장하지 않았다.
실제 다인 네트워크·GPU 플레이 검사는 수행하지 않았다.

자기 임시 805,776,839 bytes를 폐기했고 남은 Temp/자기 프로세스·정리 예외는 없다.
로컬 최소 근거: `Saved/BuildChecks/WeaponAutoStow-20261103/CompletionResult.json`.
모듈/스냅샷은 폐기했으므로 해시는 당시 검사 증거다.

## 애니메이션의 무기 보유·휴대 상태

`URPGPlayerAnimInstance::NativeUpdateAnimation`은 게임 스레드에서 로드아웃의
공개 표현 상태를 읽어 `bHasActiveWeapon`, `WeaponCarryState`,
`bUseArmedLocomotion`을 함께 갱신한다. `ABP_Player`는 마지막 값으로 기존
무장 레이어와 맨손 상태 머신을 선택한다. `CurrentEquippedWeaponTag`의 유효성이나
전투 컴포넌트 내부 경로를 애니메이션 평가 중 조회하지 않는다.

| 활성 무기 | 휴대 상태 | 이동 포즈 |
|---|---|---|
| 없음/아직 복제되지 않은 참조 | Stowed로 정규화 | 맨손 |
| 있음 | Stowed | 맨손 |
| 있음 | Drawn | 무장 |
| 있음 | Sheathing | 무장: 수납 notify가 Stowed로 바꿀 때까지 |

무기 보유는 손에 들고 있는지와 별개다. 수납 시에도 기존 로드아웃의 능력·입력과
연결된 레이어는 유지한다. 무장 진입 0.2초·맨손 복귀 0.4초, Relax 5초와 자동 수납
10초는 유지한다. 재초기화/종료·소유자 부재·해제된 컴포넌트·소멸한 무기는 중립 상태로
초기화한다. 클라이언트도 기존 복제된 표현 상태를 사용하며 새 복제 필드는 추가하지 않는다.

`Scripts/Editor/ConfigurePlayerAnimWeaponState.py`는 기본적으로 읽기 전용 검사이며,
명시한 독립 프로젝트에서만 기존 ABP 조건을 이전한다. 실제 네트워크 전달과 GPU 포즈
관찰은 native 역할별 상태 모형·그래프 검사와 구분한다.

2026-11-03 검증: 정상 Editor 빌드 19작업·입력 1,414개 불변, 같은 모듈에서 native
7검사 성공(새 상태 검사와 기존 상태 검사 오류/경고0). 기존 로드아웃 5검사의 경고7개는
구분한다. ABP 작성·새 프로세스 재로드의 관련 BP5 정상 컴파일과 나머지 그래프 동일성,
원본 설치본 SHA 일치를 확인했다. 노드 좌표 API 접근 실패2회는 사본에서만 발생해
공식 그래프 API로 수정했으며 성공한 native 검사를 반복하지 않았다. 자기 임시/후보
437416244 bytes를 폐기했고 잔여/예외는 없다. 근거는 로컬
`Saved/BuildChecks/AbpCarryState-20261103/CompletionResult.json`이다.
