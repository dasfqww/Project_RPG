# 「폐광의 실종자」 M03·M04 플레이 연결

기준: [첫 챕터 기획 v0.2](SCENARIO_FIRST_CHAPTER_PROPOSAL.md)와 확정 C1~C9. M03 조사와 후속 M04 접근 실습을 기존 성장 경로에 연결한다.

## 진입과 조작

정상 `Project_RPGEditor` 빌드와 조사 배치가 설치된 환경에서 실행한다.

```powershell
.\Scripts\Start-TrainingDevelopment.ps1 -DungeonProfile Intro1 -ChapterOne
```

기존 로비에서 개발 로그인·캐릭터 선택 후 이야기 창으로 M01을 수락하고 미라·로엔의 설명을 확인한다. M02를 수락해 기존 훈련을 성공한다. 이미 승인된 훈련 실적은 다시 수행하지 않는다. M03을 개인 수락한 뒤 기존 입문 1 입장으로 외곽에 도착한다. 현장의 의뢰 표식에서도 M03을 수락할 수 있다. 로컬 개발 실행기는 기존처럼 Memory 저장을 사용하므로 클라이언트 재접속 중에는 유지되지만 실행기 종료 시 개발 서버의 기록은 폐기된다. 운영 저장은 기존 PostgreSQL 저장소를 사용한다.

시작 지점 남쪽 길을 따라 **화물이 남은 수레 → 안쪽 버팀대 → 점검 통로의 생존 신호** 순서로 접근하고 기존 상호작용 입력으로 조사한다. 현재 개인 목표와 승인된 관찰 문구는 각 단서의 화면 표식에 표시한다. 활성 M03은 기존 HUD 추적 기능에도 연결한다. 다른 의뢰를 이미 추적 중이면 그 선택을 덮지 않는다.

세 번째 목표의 저장이 확정되면 M03은 자동 완료한다. 점검 통로 옆 ‘현장 목표’에서 M04 「접근로 확보」를 제시한다. 수락은 본인이 선택해야 하며, 기존 Intro1 접근·회전 실습 성공은 별도로 요구한다. 조사만으로 XP·SP·스킬·광석을 지급하거나 실습 완료를 만들지 않는다.

### M04 접근 실습

M04 수락 후 생존 신호 표식은 북쪽 기존 실습장으로 안내한다. 01 출발 지점 확인 → 02 표시 밖에서 돌진 베기를 시작해 안에서 정상 종료 → 03 공격 표시 안에서 회전 베기를 정상 종료한다. 화면의 기존 접근 실습 안내가 현재 진도와 실제 슬롯 키를 표시한다. 수락한 M04는 기존 HUD 추적이 비어 있을 때만 추적한다.

회전 베기는 Training 정산으로 습득한 뒤 **로비 스킬 구성에서 직접 편성·저장**해야 한다. 전투 공간에서 편성을 바꾸거나 새 스킬을 자동 편성하지 않는다. 미편성 상태라면 기존 로비 복귀로 구성하고 재입장한다. 저장한 M03 단서와 M04 수락은 유지되며 실습 동작은 새 시도에서 수행한다.

개인 실습 3/3은 정산 영수증과 구분한다. 생존 신호 표식은 개인 실습 완료 때 ‘파티 완료와 정산 저장 확인 중’을 표시하고, 서버 조회에 M04 Completed가 확인된 뒤에만 ‘입문 1 실적 저장 확인’으로 바뀐다. 정산 XP100·광석2·도약 습득은 기존 Intro1 정산이 담당하며 M04 기록은 같은 지급을 반복하지 않는다. 유효한 과거 Intro1 실적이 있으면 기존 실적 인정 경로를 사용한다.

## 구현 경계

- 외곽은 기존 `L_ProgressionIntro1`의 남쪽 동선에 추가한 블록아웃이다. 수레의 남은 짐, 봉쇄 안쪽 지지대, 별도 점검 통로를 서로 다른 형태로 배치한다. 기존 시작점·실습 구역·게임모드·정산은 보존한다.
- `ARPGChapterOneClue`는 기존 `ARPGNarrativeInvestigation`의 서버 승인 RPC·거리·시야·생존·최종 입장·연결 세대 검사를 사용한다. 클라이언트가 단서 ID나 완료 진도를 제출하지 않는다.
- 조사 영역은 소모되지 않는다. 선행 전 조사와 재조사도 가능하지만 서버는 활성 목표에만 새 증거를 반영한다. 같은 사건 재전송은 기존 영수증을 반환하며, 같은 단서의 새 사건도 이미 완료한 목표를 누적하지 않는다.
- 단서 문구는 현재 인증 캐릭터의 서버 조회에서 해당 목표 완료를 확인한 뒤 표시한다. 단순 근접·소리·창 열기는 목표 근거가 아니다. 생존 신호는 문자로도 전달한다. 전원 생존·다온의 정체·봉쇄 목적은 이 구간에서 확정하지 않는다.
- 초판 조사 연결은 기존 **개인 현장 조사** 경로다. 동행자는 각자 수락·선행 조건을 충족하고 같은 오브젝트를 재조사할 수 있다. 다른 사람의 과거 진도를 복사하거나 접속하지 않은 사람을 완료시키지 않는다. 파티원 자동 공동 인정은 이 개인 경로에 포함되지 않는다.
- `chapter01.json`은 카탈로그 v2에서 M01~M05를 등록한다. 개별 의뢰를 전체 챕터 완료나 계정 스킵 자격으로 승격하지 않도록 챕터 완료 정의는 아직 등록하지 않는다. 기존 스킵 시스템·정책과 성장 입장 조건은 그대로다. M06 이후 실제 제작은 후속 범위다.

## 서버 정의와 저장

선택형 `autoComplete`의 기본값은 false다. 명시한 의뢰만 마지막 승인 목표를 기록하는 동일 저장 트랜잭션에서 Completed로 바뀐다. 레거시 보고 의뢰는 기존 ReadyToReport·보고 절차를 유지한다. 수락·선행·버전·중복·챕터 projection·명령 영수증은 기존 경로를 쓴다.

던전 목표의 선택형 `allowPriorCompletion`도 기본값은 false다. M02 Training과 M04 Intro1의 전투 실습에만 true를 작성했다. 본인의 기존 확정 정산 수령 근거·정확한 던전/난이도·현재 의뢰 정의 버전·동일 의뢰 내 증거 재사용 금지를 계속 검사한다. 수락 전 단서 조사나 대화 사실을 소급하지 않는다. 실습 정의가 바뀌어 옛 실적이 새 실습을 증명하지 못하면 저자가 이 옵션을 활성화해서는 안 된다.

운영 적용은 `Narrative:CatalogPath`로 이 파일을 명시한다. 기존 카탈로그를 운영 중 교체할 때 기존 저장 의뢰를 삭제하지 않고 합쳐서 버전·이행을 확인해야 한다. 개발 옵션은 기존 빈/개발 카탈로그를 운영 서버에서 자동 대체하지 않는다.

## 저작과 검증

`Scripts/Editor/CreateChapterOneExterior.py`는 기존 맵의 조사 소유 태그만 추가하며 다른 액터를 삭제하지 않는다. 기본은 읽기 전용이고 `-RPGCreateChapterOne`일 때만 미배치 구간을 추가한다. 별도 에디터에서 `RPG_CHAPTER_ONE_REPORT` 절대 경로를 지정한다. 같은 태그가 이미 있으면 재생성하지 않고 검사한다.

`Scripts/Tests/Run-ChapterOnePlaytest.ps1`은 사설 백엔드와 실제 UE 서버·클라이언트로 기존 훈련 입력·정산을 수행한 뒤 M03을 진행한다. 첫 수레 승인 뒤 클라이언트 프로세스를 끝내고 같은 캐릭터로 재접속해 나머지 단서를 조사한다. 자동 드라이버는 CharacterMovement 이동과 기존 Enhanced Input 상호작용 액션을 사용하며 진도 설정·조사 HTTP 직접 제출을 사용하지 않는다. M04 보드에서는 기존 NPC/현장 안내의 대화 진입 함수를 호출한다. 물리 키보드 입력이나 사람의 서사 이해도 평가는 별도다.

`-ApproachPractice`를 추가하면 M04 현장 창의 제시/수락 버튼을 선택하고 기존 실습장까지 실제 이동·퀵슬롯 사용을 진행한다. 검사 캐릭터의 회전 베기는 Training 종료 후 일반 Player skill-configuration API로 명시 편성·저장한다. 이 모드의 훈련 드라이버는 실제 최대 차지 단계가 확인된 뒤 입력을 떼어, 프레임 지연 중에도 벽시계의 2초를 최대 차지로 잘못 취급하지 않는다. 획득·레벨·목표·실습 완료 값을 직접 설정하지 않는다. 백엔드 검사는 정산 전 기록 거절, 정산 후 M04 완료, 응답 유실 재전송, 반복 후보 제거와 성장 재지급 방지도 확인한다.

2026-11-16 검증: 독립 전체 Editor 빌드와 수정 증분 링크 성공. 맵 저장 후 새 프로세스에서 조사 배치25개와 기존 실습 배치26개·시작점4개·게임모드 보존을 확인했다. 실맵 전용 서버에서 드러난 이름표 렌더 컴포넌트 누락 접근을 조사 액터·현장 보드 양쪽에서 수정했다. 공유 정상 빌드는 다른 담당의 Build6에서 최종 변경3개 컴파일/링크 성공을 확인했으며, 아래 실제 플레이 증거는 독립 모듈 기준이다.

### M04 후속 검증 — 2026-11-17

M04 수락 전/진행/개인 실습 완료·정산 대기/저장 완료의 현장 문구를 연결하고 빈 HUD 추적에만 M04를 제안했다. 신규 백엔드 검사와 기존 Narrative/NarrativeInteraction 3개 suite가 통과했다. 정산 전 완료 거절·정산 후 자동 완료·같은 요청 재전송·반복 후보 제거·성장 무재지급을 확인했다.

Iris 전용 서버·렌더링 클라이언트의 실제 Training 정산 → M03 수레 저장·프로세스 재접속 → 나머지 단서 → M04 현장 버튼 수락/안내·HUD 추적 → 실습장 이동·돌진/회전 승인 → M04 Completed·완료 표식·정산 결과 화면을 확인했다. XP100→200, SP6·도약 습득/자동 편성 없음과 반복 조회의 성장 불변이 통과했다. 실측 돌진 이동량에 맞춰 영역 경계 밖에서 시작해 안에서 마쳤으며 목표 값을 직접 설정하지 않았다.

실행은 기존 정상 타깃의 고정 링크 입력과 본인 CPP3를 사용하는 사설 모듈 기준이다. 준비 중 구형 전송 인터페이스 호출 오브젝트의 불일치를 발견해 관련 현재 소스9개를 동일 헤더로 다시 컴파일했다(의존 소스 내용 수정 없음). 같은 보정과 최종 M04 소스는 정상 모듈에도 컴파일·링크로 반영했다. 메모리 부하로 중단한 독립 전체 타깃 시도는 빌드 성공으로 집계하지 않는다. 최대 차지 드라이버의 벽시계 의존과 초기 돌진 시작 위치 실패 역시 최종 통과와 구분해 기록했다.

최종 결과·소스/모듈 해시·화면은 로컬 `Saved/BuildChecks/ChapterM04-20261116/`에 남긴다. 검증용 입력·OBJ·DLL·PDB·UserDir·캐시는 정리한다. 개발 인증·Memory HTTP 범위이며 실제 Steam·PostgreSQL 재시작·다인 실습/전체 챕터 검증은 포함하지 않는다.

## M05 생존자의 증언

`Start-TrainingDevelopment.ps1 -DungeonProfile Intro2 -ChapterOne`로 M01~M05를 이용한다. M04와 실제 Intro1을 완료한 뒤 같은 현장 목표에서 M05를 수락하고 입문2에 입장한다. 입문2 북동쪽의 개방된 점검실에서 다온을 확인한다. 첫 상호작용은 발견 사건의 서버 승인이고, 저장 후 다시 상호작용하면 D05 증언을 듣고 구조 요청을 확인할 수 있다. NPC와 점검실은 기존 원시 메시를 재사용한 블록아웃이다.

발견은 기존 조사 컴포넌트가 인증된 연결 세대·살아 있는 캐릭터·거리·시야·확정 입장을 확인한 뒤 `CH01.Daon` 서버 사건으로 저장한다. 보이지 않는 서버 조사 대상은 별도 입력 지점이 아니며, 다온을 제거하면 함께 제거한다. 서버가 발견을 저장하기 전에는 D05 선택을 노출하지 않는다. 승인 발견과 증언은 개인 영속 성과이며 재접속·재조사·중복 전달로 늘어나지 않는다. 동행자의 발견을 다른 캐릭터에게 복사하지 않는다.

전투 목표는 기존 Intro2의 서로 다른 공격 기회 2회와 실제 정산을 재사용한다. 발견·대화만으로 전투 정산을 요청하지 않는다. 이미 유효한 Intro2 영수증이 있으면 전투 목표만 인정하고 다온의 개인 목표를 꾸며내지 않는다. 부족한 서사만 진행할 때도 반복 입장한 점검실은 전투 없이 접근할 수 있으며, 진행 보존 귀환/명시 포기는 기존 던전 메뉴를 사용한다. 새 시도의 전투를 다시 끝내야 M05가 완료되는 조건은 추가하지 않는다.

발견·증언·정산 근거가 모두 확정되면 기존 코디네이터가 의뢰를 완료하고 추적을 해제한다. 다온의 다음 대피 경고를 제공하지만 M06의 구출·방어 성공이나 전체 챕터 완료는 만들지 않는다. 의뢰 완료·재조회는 XP·SP·광석을 추가 지급하지 않는다. C1~C9와 기존 성장·스킬 수동 편성 정책을 유지한다.

`Run-ChapterOnePlaytest.ps1 -RuntimeProjectRoot <호환 프로젝트> -ChapterFive`는 실제 훈련/M03/M04 뒤 다온 발견 저장, 클라이언트 재시작과 발견 복원, D05의 UMG 선택, 실제 Intro2 전투·정산, M05 자동 완료 저장을 확인한다. 백엔드 회귀는 과거 전투 실적만 인정·발견 전 증언 거절·동시 중복·연결 세대 변경·영속 발견·성장 불변을 검사한다. 작은 증거는 `Saved/BuildChecks/ChapterM05-20261117`에 보존하고 실행 사본/캐시는 폐기한다. 고정 사본의 검증은 다른 담당의 후발 HUD 변경·실제 Steam/PG 재시작·다인 플레이 검증으로 확대하지 않는다.
