# 오른쪽 아이템 퀵슬롯

## 구성과 조작

- 아이온2의 스킬/아이템 영역 분리를 참고한다. 기존 왼쪽 스킬·중앙 아이덴티티는 유지한다.
- 오른쪽에는 회복 물약 전용 `X` 슬롯 하나와 일반 소모품 `F1~F8` 슬롯 여덟 개를 배치한다. 일반 슬롯은 네 칸씩 두 줄이다.
- 빈 칸 클릭 또는 슬롯 우클릭으로 가방의 소모품을 선택한다. 선택 후 등록하며, 이 과정에서 아이템을 소비하지 않는다. 우클릭 메뉴의 `슬롯 해제`는 바로가기만 지운다.
- 가방에서 슬롯으로 드래그하는 기존 방식도 유지한다. 물약 칸은 현재 아이템 카탈로그의 `GameItem.Consume.Potion.Red.*` 회복 물약만 받는다. 일반 슬롯은 기존 소비 정책을 따른다.
- 등록한 아이템은 클릭 또는 현재 설정된 단축키로 사용한다. 단축키 표시도 실제 매핑을 읽는다. `X`는 수동 회복이며 자동 사용은 별도 버튼으로 선택한다.
- 아이콘·현재 스택 수량·공유 명령 대기/복구 상태를 표시한다. 빈 칸은 `HP` 또는 `+`로 구분한다.

## 자동 회복

- 기본값은 OFF, HP 기준은 50%이다. 기준 버튼을 누르면 25% → 50% → 75% 순으로 순환한다.
- 켜져 있고 현재 HP가 기준 이하일 때, 살아 있는 로컬 소유 Pawn의 등록 물약을 최대 5초에 한 번 자동 요청한다. 5초는 보조 사용 주기이며 서버 아이템 쿨타임이 아니다.
- 가방 등 커서가 표시되는 조작, 일시정지, 액션바 전환(탑승 등), 사망, 아이템 명령 대기/복구/권한 미준비 중에는 자동 사용하지 않는다. 수동 사용과 같은 `TryConsumeInventoryItem` 경로를 이용한다.
- 클라이언트가 직접 회복 효과나 수량을 변경하지 않는다. 기존 서버의 보유·정의 버전·소비 정책·살아 있는 아바타·탑승·영수증/복구 검증을 유지한다.
- 자동 사용과 HP 기준은 Pawn 수명 안의 로컬 설정이다. 아이템이 소진되어 배정이 비면 자동 사용을 끈다. 재접속·재빙의 설정 저장은 추가하지 않는다.

## 구현 경계

- `ARPGHUD`가 기존 `HorizontalBox_QuickSlot` 영역을 `URPGItemQuickSlotBar`로 대체한다. 원본 WBP 에셋을 수정하지 않는다. 새 모듈을 만들 수 없으면 원본 영역을 숨기지 않는다.
- 셀은 기존 `URPGQuickSlotWidget`의 클릭 취소, 드롭, 비동기 아이콘, 서버 소유 ItemId, 공유 인벤토리 모델과 붉은 호버 프레임을 재사용한다. 네이티브 셀에는 위젯 트리를 코드로 구성한다.
- 일반 소비 인덱스 0~7을 유지하고 회복 물약은 8번으로 추가한다. 서버와 클라이언트 모두 용량은 9칸이다.
- Controller 소유의 transient 입력 구성에 F1~F8/X 기본값을 만든 다음 기존 사용자 키 저장값을 복원한다. 원본 입력 에셋·스킬 매핑은 수정하지 않는다. 입력 설정의 기본값 복원도 확장된 구성에 맞춘다. 기존 `QuickItem.F1` 별칭은 첫 일반 슬롯의 숨긴 별칭이며 같은 액션을 중복 바인딩하지 않는다.
- 기존 숫자 기본 키를 기준으로 저장한 아이템 키 변경은 선택한 키를 유지한 채 새 기본 키로 메타데이터를 이관한다. 이미 새 기본 키로 저장한 명시적 설정이 있으면 그것을 우선한다. 초기화 중 설정 파일을 별도로 저장하지 않는다.
- 현재 소비 정의에는 공통 쿨타임이 없다. 임의의 UI 타이머를 실제 쿨타임처럼 표시하지 않는다. 봉혼석·신규 지속 버프 자동 갱신·아이템 배정 영속 저장·백엔드 API 변경은 포함하지 않는다.

## 검증

- 유지할 회귀 검사: `ProjectRPG.Item.QuickSlot.ExpandedDefaults`, `AutoRecoveryThreshold`, `NativeRightBar`.
- 기존 클릭/드롭/복구·보유 ID/수량/소진·클라이언트 재빙의 검사와 HUD 수명 검사를 함께 확인한다.
- 결과는 `Saved/BuildChecks/ItemQuickSlots-20261118/`의 작은 로컬 요약에 기록한다. 원본 설치 DLL과 다른 담당자의 에디터는 검증 입력으로 교체하지 않는다.

### 2026-11-20 표시 갱신 최적화

- 기존 아이템 ViewModel은 메모리에 있는 아이콘을 즉시 표시하고, 미로드 아이콘은 비동기로 요청한다. 같은 아이콘 요청은 재사용하며 슬롯 재연결·해제 및 아이콘 교체 시 이전 요청을 취소한다.
- 실제 오른쪽 HUD 셀의 비동기 로딩 경로에서 수량 갱신 시 동일 브러시를 다시 설정하지 않고, 슬롯 갱신마다 공유 명령 표시를 한 번 계산한다. 비동기 완료 시에는 새 아이콘에 맞춰 표시를 갱신한다.
- `ProjectRPG.Item.QuickSlot.ViewModel.KeepsActiveStateOnQuantityRefresh`는 스택 수량 변경 중 슬롯 활성 상태가 깜빡이지 않고 연결 해제 시 표시가 초기화되는지 확인한다.

### 2026-11-18 검증 결과

- 게시 `03a59968` 기준 사본에 본인 소스/설정 13개를 덮어 고정한 전체 UHT/Editor 빌드·링크가 통과했다. 마지막 버튼 텍스트 폭 수정까지 포함한 DLL은 `4952E23F98AB1889AEA5DDC5C4171F99C29DD67E7B130187F30170396902CBD7`이다.
- 실제 모듈을 로드한 native 22개 검사 모두 Success, 오류 0이다. 기존 입력 검사 에셋 경고 141개와 기존 보유 ID/스킬 등록 검사의 예상 거절 경고 5개는 별도로 남긴다. 신규 3개 검사 및 시각 검사의 오류·경고는 0이다.
- D3D12/Slate에서 실제 HUD의 오른쪽 영역 대체, 물약 배정, 수량·아이콘·키, 9개 셀, 1280×720 / 1920×1080 / 2560×1080 배치를 확인했다. 최종 PNG 3개와 하단 바 발췌를 로컬에 남긴다. 이는 격리된 소유자/아이템 fixture이며 실제 HTTP/PG 소비·물리 키 입력·다인/Shipping 검증과 구분한다.
- 게시 기준의 기존 탈것 테스트 두 파일이 같은 `FRidingRegistrationFailures` C++ 심볼을 선언해 최초 전체 링크가 실패했다. 검증 사본의 UI 테스트 클래스 이름만 구분했으며, 원본의 다른 담당자 미커밋 수정과 게시 범위는 유지했다. 이 조정은 제품 커밋에 포함하지 않는다.
- 첫 시각 실행의 fixture 시작 데이터 누락과 기존 무소유 아이템 우클릭 경로 검사 실패, 버튼 글자 잘림을 최종 성공과 구분한다. 명시적 빈 시작 데이터, 바인딩된 아이템 셀에 한정한 메뉴 처리, 버튼 텍스트 폭 보완 뒤 동일 범위를 다시 통과했다.
- 빌드 사본·오브젝트·PCH·DLL·PDB·캐시는 확인 종료 후 폐기하며, 위 모듈 해시는 당시 검증 증거이다. 원본 DLL 설치와 검증 이후 다른 담당자의 후속 변경은 이번 결과에 포함하지 않는다.
