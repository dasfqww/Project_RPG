# 로비 장비 성장·제작 화면

작성일: 2026-11-02

상태: 강화·이전 및 선택 제작·분해의 원본 UI/정상 Editor 반영 완료. 첫 구현 native4와 제작/분해 후속 native6을 구분한다. 물리 입력과 인증된 화면→HTTP 전체 흐름·PG/다인 검증은 별도다.

## 1. 이번 범위와 성장 방향

[성장 방향 1.1절](PLAYER_PROGRESSION_DESIGN_DIRECTION.md#11-부담-없는-플레이와-선택적인-고강화-2026-11-02-사용자-선택)의 낮은 부담·장비 귀속 강화·교체 시 투자 보존에 맞춰, 이미 구현된 첫 구간 명령을 실제 로비에서 사용하도록 연결한다. 기존 [장비 명령 21절](PLAYER_PROGRESSION_EQUIPMENT_TRANSACTIONS.md#21-플레이어-bp-성장-명령과-미확정-요청-복구)의 Subsystem/HTTP/영속 저장·미확정 복구를 재사용한다.

강화는 현재 +0~+3 확정 강화와 같은 부위·같은 구간의 무료 이전을 제공한다. 광석 비용 2/4/6과 +0 대상 제한을 유지하며, 선택 제작/분해는 5절의 후속으로 연결했다. 확률 강화·고강화 상한·실패 진척·업데이트 환산·양쪽 강화 장비 교환은 추가하지 않는다.

## 2. 실제 이용 흐름

1. 로그인·서버·캐릭터 준비 후 로비의 **장비 성장 · 제작**을 연다. 최신 소유 아이템을 한 번 조회하며 실패하면 명시적인 **장비 새로고침**으로 다시 읽는다.
2. **한 단계 강화** 또는 **강화 무료 이전**을 고르고 현재 아이템 목록에서 대상 장비를 선택한다. 원시 ID·가격·새 아이템 Record를 입력하지 않는다.
3. 단계의 전후 값, 이 장비의 공격력/최대 체력 변화와 필요한 광석 또는 무료 이전 결과를 확인한다. 이는 장비 자체의 기여이며 현재 캐릭터의 최종 피해나 비활성 무기의 실제 적용을 보장하는 수치가 아니다.
4. **비용과 변경 내용 확인** 뒤 별도의 **확인한 내용으로 실행**을 눌러 전송한다. 확인 취소·화면 닫기는 로컬 확인만 취소하며 전송한 원본 요청을 취소하거나 지우지 않는다.
5. 성공 또는 확정 거절 후 최신 소유 아이템을 다시 조회한다. GET 실패 시 완료 상태로 꾸미지 않으며 새 명령은 최신 읽기가 확인된 뒤에만 준비한다.

이전은 원본 +k→0·대상 0→+k다. 두 장비의 ID·고유 효과·현재 위치/장착 상태를 유지한다. 장비를 옮기는 별도 장착 명령이나 강화량 합산을 보내지 않는다.

## 3. 선택·확인과 복구 경계

- 현재 Ready 투영의 정확한 7종/Version1·명시된 FirstSlice/RuleVersion1·단계0~3만 선택한다. 잠금·만료·비귀속·보관함/우편·누락 성장 상태·잘못된 장착 부위는 제외한다. 최종 권한·정책은 backend가 다시 검사한다.
- 광석은 가방의 사용 가능한 정확한 재료 ID/Version1에서 안정 ID 순서로 선택한다. 현재 필요한 수량만 충족하는 기대 ID/Int64 Revision을 보내며 가격이나 수량 변경을 서버에 지시하지 않는다. 후보 스택은 기존 상한15개다.
- 확인 단계의 장비 ID/Revision/현재 단계와 비용 스택 ID/Revision을 실제 실행 직전에 다시 대조한다. 선택·문맥·조회 결과가 달라지거나 만료되면 이전 확인을 재사용하지 않는다. 클라이언트 조회 뒤의 경합은 기존 서버 CAS/원자 처리로 거절된다.
- 계정/endpoint/선택 캐릭터와 월드/컨트롤러를 현재 문맥으로 재확인한다. 화면 수명 종료 때 이벤트를 해제하며 이전 문맥의 선택과 확인은 새 문맥으로 넘기지 않는다.
- 캐릭터가 선택되면 화면이 닫혀 있어도 로컬 journal을 읽어 미확정 요청을 복구한다. 이 과정은 자동 결제/재시도를 보내지 않는다. 결과 미확정·인증 필요는 **이전 작업 결과 재확인**에서 원래 명령을 재전송하며 비용·장비를 다시 고르거나 새 RequestId를 만들지 않는다.
- 장비 쓰기/읽기 중에는 새 이동·성장 작업을 막는다. 미확정 결과가 있으면 새 입장·생성·캐릭터 변경은 막되 기존 세션 복원/조회·탈퇴 경로는 유지한다. 서버의 유효 리스 거절을 해결할 수 있어야 하며 원래 영수증 재확인은 리스 중에도 허용한다.
- 영수증의 과거 Record를 투영이나 GAS에 직접 적용하지 않는다. 이번 범위는 로비 명령과 최신 조회이며 다음 전투의 장비 복원은 기존 경로를 따른다.

## 4. 구현과 검증

신규 `RPGEquipmentGrowthModel`은 선택/비용/전후 비교와 동일 확인 대조를 담당하고, 신규 `RPGEquipmentGrowthWidget`은 기존 Subsystem의 상태/이벤트를 사용하는 native UMG 화면이다. 기존 `RPGOnlineLobbyWidget.h`와 `RPGOnlineLobbyWidget.cpp`/`RPGOnlineLobbyMenu.cpp`의 실제 메뉴·패널·동작 guard에 연결한다.

독립 작성 시 Intro1 정상 빌드의 전체 Source 고정 읽기를 확인해 원본 편집을 중단하고 별도 경로에서 신규5/기존3을 작성했다. 이후 명시적인 공유 해제와 기존3 baseline SHA·신규5 미존재를 재조회하고 원본8을 적용했다. 다른 담당의 장비 명령/HTTP·GAS·Source/에셋은 수정하지 않았다.

집중 검증은 미리보기/대량 Int64 Revision/확인 무효화·재료 부족/무료 이전·기존/잠금/만료/지원하지 않는 아이템 제외·미확정/새 조회/실제 메뉴와 무인증 fail-closed를 대상으로 한다. 기존 장비 명령 native/HTTP 성공 근거와 이번 화면 검증은 서로 다른 범위로 취급한다. 실제 물리 입력·HTTP 화면 전체 흐름·PG/다인·운영 Steam은 수행한 근거가 있을 때만 별도로 기록한다.

정상 Editor의 첫 UHT/33작업과 보완 후5작업이 각각 종료0이었다. 두 빌드에서 컴파일 입력1380개의 파일집합/SHA가 전후 동일했다. 첫 빌드의 기존 포커스 검사 C4996 경고1과 최종5작업의 경고0을 구분한다. 최종 모듈은 `BF5CFA5A0731EC5F4DCA8C6F943CC24BA42CEFEFE72D242862CF5B54696AFAC1`이며, 닫힌 Source/Config/모듈/Plugin1203 사본에서 실제 같은 DLL의 로드를 확인했다. 사본을 취득하자마자 공유 빌드/원본 전체 입력·출력 예약을 해제했다.

## 5. 선택 제작과 +0 목표 장비 분해 (2026-11-02 후속)

상태: 원본7 적용·정상 빌드·native6 완료. 앞 절의 원본 강화/이전 native4 완료와 이번 후속의 실행 근거는 구분한다.

드롭을 얻지 못해도 원하는 장비에 도달할 수 있도록 [기존 제작/분해 계약](PLAYER_PROGRESSION_EQUIPMENT_TRANSACTIONS.md#17-2026-11-01-증표-선택-제작과-목표-장비-분해)을 실제 화면에 연결한다. backend 정책·가격·보상·반환 규칙은 변경하지 않는다.

- 로비의 **장비 성장 · 제작**에서 기존 강화/무료 이전과 함께 **목표 장비 선택 제작**·**남는 +0 목표 장비 분해**를 선택한다. 안정된 버튼/위젯 이름은 유지한다.
- 제작은 정확한 목표4종(인내/순환 대검·목표 상의·장갑) 중 하나를 고른다. 사용 가능한 가방의 캐릭터 귀속 증표8개를 ID/Int64 Revision 후보로 보내며, 서버가 새 ID의 캐릭터 귀속 +0 장비1개를 만든다. 잠금·만료·성장 상태가 있는 재료·999개 초과 스택·다른 버전/재료는 제외한다.
- 분해는 지원하는 명시적 +0 목표 장비1개만 소모하고 증표1개를 돌려받는다. 시작 장비·강화 장비는 보호하며, 분해로 장비와 고유 효과가 사라짐을 실행 전 표시한다. 장착 중이면 해당 칸도 비워짐을 별도로 알린다. 일괄 분해나 자동 분해는 없다.
- 제작품과 분해 증표는 가방 우선·초과분 우편이라는 기존 서버 전달 정책을 안내한다. 클라이언트가 결과 ID/Record·실제 지급 위치를 지정하지 않는다.
- 제작에는 출력 정의명/증표 비용/후보 ID·Revision을, 분해에는 원본 ID·Revision·단계를 포함해 확인 내용을 비교한다. 출력 변경·재료 Revision 변화·미확정 이전 요청·최신 읽기 필요 상태에서는 옛 확인을 보내지 않는다.
- 명시적 확인과 journal/원본 재확인·최신 GET·문맥/로비 guard는 첫 구현을 재사용한다. 분해를 누른 뒤 응답이 없다는 이유로 재료를 새로 고르거나 장비/증표를 로컬에서 되돌리지 않는다.

확인 대상은 네 출력·증표8/분리 스택/Int64·잘못된 출력/부족·잠금/만료/잘못된 스택·출력/재료 변경의 확인 무효화·시작/강화/잠금/미설정 장비 분해 거절·미확정/최신 읽기 guard와 실제 native UMG의 모드별 선택란이다. 기존 강화/이전 검사도 새 확인 값과 화면 변경의 영향을 확인한다. 현재 고강화 확률/상한·GAS/아이덴티티·HUD/백엔드는 이번 수정 범위에 포함하지 않는다.

HUD 전체 컴파일 입력 고정을 피해서 사본에서 작성한 뒤, 공유 자원의 명시적 해제와 기존7 baseline SHA를 대조해 원본에 적용했다. 정상 Editor UHT/10작업/27.25초·종료0·컴파일 경고0이며 입력1389개의 파일집합/SHA가 전후 동일했다. 최종 `EAFE352CE1BB63707C09AF37C7A895DE421CC32B64FFC2AEFF53B79D7CC8622F`의 닫힌1212 사본을 취득한 즉시 공유 빌드/전체 입력·출력 예약을 해제했다.

`25ec20cf1e184ba995de0ecdc952e066`에서 실제 같은 DLL의 로드와 native6 Success/오류0·UE 종료0·사본 전후 동일을 확인했다. 새 `ProjectRPG.UI.EquipmentGrowth.CraftPreviewAndCosts`/`DismantleAndRecovery`는 무경고이며 기존 모델2/화면1/메뉴1도 통과했다. 기존 캐시139와 최소 PlayerInput fixture2의 경고141·`strictWarningsPassed=false`·기동 Error15/검사 시작 후 Error0은 유지한다. UI 모드/기대값의 native 검사이며 실제 클릭의 인증 HTTP/PG·다인 또는 렌더 화면 확인으로 확대하지 않는다.

자기 runtime/사본/DLL/UserDir·캐시와 원본 적용을 마친 독립 작성본 **205,081,420 bytes(195.58MiB)**·링크11을 폐기했다. 최종 자기 임시·프로세스·정리 예외0이며 원본 Source/Binaries·Intermediate·공유 DDC/다른 담당의 작업은 유지했다. [ImplementationResult.json](../Saved/BuildChecks/EquipmentCraftUI-20261102/ImplementationResult.json)에 소스7/모듈 해시·6개 결과·정리 수치를 보관한다. 폐기 사본의 해시는 당시 증거다. 유지할 native 검사는 원본 `Private/Tests/RPGEquipmentGrowthUITests.cpp`이며 `Automation RunTests ProjectRPG.UI.EquipmentGrowth`로 선택할 수 있다. 이번 기능의 Source7/이 문서·조율표 본인 행/완료 항목만 커밋·푸시하고 다른 담당의 미커밋 변경은 포함하지 않는다.
