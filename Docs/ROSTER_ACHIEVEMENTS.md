# 원정대 업적

로비의 **모험 → 원정대 업적**을 펼치면 같은 월드의 모든 캐릭터가 쌓은 진행도와 달성일을 볼 수 있다. 달성일은 목표를 채운 실적의 서버 시각을 사용한다. 처음 열 때 기존 업적은 목록에 표시하고, 접속 중 미달성에서 달성으로 바뀐 업적은 화면에 알린다.

| 업적 | 인정하는 실적 |
|---|---|
| 폐광 일반 첫 클리어 | `Progression.FirstBoss`의 `Normal` 정산 명단에 원정대 캐릭터가 포함된 첫 세션 |
| 폐광 일반 10회 클리어 | 같은 조건을 만족하는 서로 다른 세션 10개 |
| 폐광의 실종자 직접 완료 | M08 마지막 보고로 서버가 확정한 `CH01` 완료. 이야기 스킵은 제외한다. |

## 저장과 조회

PostgreSQL 마이그레이션 18은 기존 던전 정산과 이야기 명령 영수증을 읽어 당시 원정대의 실적을 복원한다. 이후 영수증이 추가될 때 같은 트랜잭션 안에서 원정대 실적을 기록한다. 던전 실적은 원정대와 세션당 한 번, 직접 완료한 챕터는 원정대와 챕터당 한 번 기록한다. 보상 배달 재시도, 파티에 속한 여러 캐릭터의 중복, 같은 보고 재전송은 횟수를 늘리지 않는다. 개발용 Memory 저장소도 같은 인정 규칙을 사용한다.

백엔드 업적 카탈로그는 판정에 사용할 실적 종류, 콘텐츠 ID, 난이도, 목표 횟수, 표시명을 정의한다. 같은 실적을 쓰는 업적은 정렬된 날짜 목록을 공유한다. 첫 번째와 열 번째 달성일은 각각 첫 번째와 열 번째 영수증 시각이다. [업적 정의](../Backend/ProjectRpg.Backend/Achievements/catalog.json) · [영속 저장과 소급](../Backend/Database/Migrations/0018_roster_achievements.sql)

플레이어 인증으로 `GET /api/characters/{characterId}/achievements`를 호출한다. 서버는 캐릭터 소유권을 확인하고 해당 캐릭터의 원정대를 조회한다. 응답의 `entries`에는 각 업적의 `id`, `title`, `target`, `progress`, `earnedAt`이 들어간다. 달성 전에는 `earnedAt`이 비어 있다. 로비와 던전 클라이언트는 캐릭터 선택, 업적창 열기, 정산 상태 전환, 이야기 응답에 맞춰 다시 읽는다. 접속 중 누락된 갱신도 주기적으로 확인한다.

## 회귀 검사

`dotnet run --project Backend/ProjectRpg.Backend.AchievementTests`로 Memory 검사를 실행한다. 같은 검사를 PostgreSQL에서 실행할 때는 비어 있는 일회용 `achievements_test` 데이터베이스의 연결 문자열을 `RPG_ACHIEVEMENTS_TEST_DATABASE`에 설정한다. 검사는 이전 마이그레이션까지 적용한 뒤 기존 캐릭터의 9회 실적과 직접 보고를 생성하고, 마이그레이션 18 적용 후 부캐의 열 번째 클리어를 확인한다.

언리얼 자동화 검사 `ProjectRPG.Achievements.SnapshotAndNotifications`는 진행도와 달성일 해석, 9회에서 10회로 넘어갈 때의 알림, 재조회와 원정대 변경을 다룬다.
