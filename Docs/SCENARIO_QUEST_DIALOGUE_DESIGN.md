# 시나리오·퀘스트·대화 시스템 통합 기획안

작성일: 2026-11-03

버전: 0.1 — 6인 기획 회의 검토를 반영한 통합 초안

상태: **기획 문서. 사용자 확정 방향과 팀 설계안을 구분하며, 기능 구현·콘텐츠 제작·실행 검증 완료를 뜻하지 않는다.**

## 1. 목적과 결정 상태

메이플스토리·던전앤파이터·로스트아크를 참고한 중형 멀티플레이 ARPG에서 시나리오, 퀘스트, NPC 대화, 던전 사건을 지속적으로 제작할 기반을 정의한다. 특정 참고 게임의 모든 기능을 그대로 도입한다는 뜻은 아니다. 기존 협동 인스턴스·캐릭터 성장·장비·서버 권위·영속 보상 구조에 연결한다.

문서의 표기는 다음과 같다.

- **확정 C:** 이번 대화에서 사용자가 선택하거나 직접 교정한 방향. 이후 제안으로 뒤집지 않는다.
- **설계안 P:** 6인 팀의 검토를 바탕으로 작성한 구체적인 기본안. 구현 계약 확정이나 사용자 승인으로 취급하지 않는다.
- **미결 D:** 게임 경험·보상·제작 범위를 바꾸므로 후속 결정이 필요한 항목. 연결된 기능의 완료 조건에 표시한다.

| ID | 사용자 확정 사항 | 적용 결과 |
|---|---|---|
| C1 | 핵심 메인 퀘스트로 지역·던전을 최초 해금 | 해금에 필요한 메인 사건을 명시하고 입장 시 확인 |
| C2 | 해금한 콘텐츠는 자유롭게 반복 플레이 | 최초 시나리오의 긴 대사·보고를 반복 입장의 필수 절차로 재요구하지 않음 |
| C3 | 서브 퀘스트는 선택 콘텐츠 | 핵심 메인 진행을 위해 서브 전체 완료를 요구하지 않음 |
| C4 | 계정에서 완료한 스토리는 부캐가 선택적으로 건너뛰기 가능 | 직접 진행 선택도 보존하며 캐릭터별 스킵 적용 결과를 기록 |
| C5 | 부캐 스킵은 스토리 스킵이며 성장 점핑은 포함하지 않음 | 레벨·SP·스킬 수준·장비를 다음 구간 기준으로 자동 보정하지 않음 |
| C6 | 미해금 콘텐츠는 입장 불가 | 파티원 각자의 해금과 기타 입장 조건 확인. 방장 자격으로 대체 불가 |

C5는 원래 퀘스트 경험치·보상을 스킵 시 지급할지까지 확정한 결정이 아니다. 해당 지급 여부는 D1이다. 기본 기능 해금과 전투 스킬의 습득 자격도 같은 것으로 취급하지 않는다.

이하 별도 C 표기가 없는 동작은 **설계안 P**다. 공개 마을·개인 스토리 공간·분기 장면은 지원 방향과 예시이며, 오픈월드·출시 지역 수·직업 수·풀더빙·일일/주간 숙제 도입을 확정하지 않는다.

## 2. 플레이 경험과 콘텐츠 종류

기본 플레이 흐름은 **인물과 사건 발견 → 의뢰 수락 → 조사·전투·상호작용 → 사건 해결 → 보고·보상 → 다음 이야기와 콘텐츠 해금**이다. 해금된 던전에서는 반복 전투와 파밍을 즐긴다.

| 종류 | 목적 | 설계 기준 |
|---|---|---|
| 메인 | 핵심 사건·챕터 진행·콘텐츠 해금 | 필수 사건을 추적하기 쉽게 표시. 다음 지역의 이유와 진입 조건 전달 |
| 서브 | 인물·지역 이해·탐색·선택 보상 | 선택 경험으로 유지. 미완료가 핵심 메인 진행을 막지 않게 작성 |
| 성장 안내 | 스킬 편성·장비·제작 등 기능 학습 | 이미 습득 가능한 기능만 요구. 기존 훈련·입문 과제와 연결 |
| 반복 의뢰 | 특정 재료·적·던전의 자발적 반복 목표 | 일회성 메인과 회차 분리. 일일/주간 제한은 콘텐츠별 별도 결정 |
| 직업·인물 전용 | 직업 정체성·인물 관계의 확장 | 공통 기반으로 표현하되 실제 제작 여부·종류·분량은 별도 |

메인과 기본 전투 보상으로 다음 핵심 콘텐츠의 기본 준비가 가능한 방향을 권고한다. 선택 서브의 보상이 실제 파티 모집의 필수 조건으로 굳어지는지는 밸런스에서 확인한다. 구체적인 수치와 분량은 이 문서에서 기존 첫 성장 구간을 변경하지 않는다.

## 3. 시스템의 책임과 연결

| 영역 | 소유하는 사실 | 다른 영역과의 연결 |
|---|---|---|
| 시나리오 정의 | 챕터·사건 관계, 필수/선택 퀘스트, 해금 규칙 | 퀘스트의 확정 결과로 챕터 진행을 해석 |
| 개인 퀘스트 | 수락, 목표 진도, 분기 선택, 보고·보상 처리, 완료 이력 | 대화의 요청과 서버 사건의 근거를 받아 진행 |
| NPC·대화 | 화자·대사·선택지·조건부 반응·연출 | 개인 진행을 읽고 허용된 수락·보고·선택을 요청 |
| 인스턴스 사건 | 이번 시도의 문·적·NPC·호위·방어·보스 순서 | 실제 사건 결과를 퀘스트 판정에 전달 |
| 영속 보상·해금 | 지급·완료 영수증, 캐릭터 해금, 계정 자격 | 확정된 퀘스트 완료/스킵 처리와 일관되게 반영 |
| 화면·표시 | 목표 추적, 대화, 진행 안내, 지도 표시 | 권위 상태를 표시하며 완료·보상을 직접 확정하지 않음 |

챕터와 대화가 퀘스트 완료를 따로 저장하지 않는다. 다른 기능이 사용할 완료·해금 조회는 하나의 확정 결과를 따른다. 퀘스트 없이 발생하는 독립적인 이야기 사건은 별도 사건 기록으로 정의하고, 생산 주체를 하나로 지정한다.

공동 사건 완료와 개인 퀘스트 완료는 다르다. 보스를 함께 처치해도 개인의 수락·선행 목표·참여·보고 조건은 각각 확인한다. 개인이 이미 완료했더라도 현재 인스턴스의 문·적·사건을 자동 생략하지 않는다.

## 4. 챕터와 콘텐츠 해금

챕터는 문제 제시, 조사·관계 형성, 사건 확대, 결전, 후일담을 조합한다. 모든 챕터가 같은 길이·같은 던전 수를 가져야 하는 것은 아니다. 현장 진행을 이어주고, 사건 해결·관계 변화·중요한 보상 선택이 있는 지점에 귀환 보고를 배치한다.

**던전 입장 해금과 해당 던전의 최초 클리어를 분리한다.** 예를 들어 폐광 조사 의뢰를 완료하면 폐광 입장이 열리고, 폐광 보스 의뢰를 완료하면 다음 지역이 열린다. 폐광에 들어가려면 폐광 클리어가 필요한 순환 조건을 만들지 않는다.

| 확인 시점 | 확인할 내용 | 실패 시 표시 |
|---|---|---|
| 콘텐츠 목록 | 개인 해금, 별도 레벨·장비 등 조건 | 잠금과 부족한 조건·관련 메인 의뢰 |
| 파티 출발 전 | 구성원별 입장 자격, 함께 진행할 사건 구간, 미수락 의뢰 | 해당 인원과 부족한 조건. 임의 추방·자동 스킵 없음 |
| 실제 입장 | 서버가 현재 자격과 입장권·멤버십 재검사 | 거절 이유와 복귀·재확인 경로 |

개인별 필수 조건을 충족한 구간만 공동 선택한다. 방장이 구간을 명시적으로 선택하되, 함께 진행 가능한 구간을 추천한다. 방장 교체나 구성원 변경으로 개인 진도를 복사하거나 시나리오를 몰래 변경하지 않는다. 사건 정의와 선택 가능한 분기 규칙의 버전은 입장 시 고정한다. 실제 분기 결과는 해당 결정 구간에서 승인·확정하며, 참가자 변경이나 재접속으로 다시 선택하지 않는다.

## 5. 퀘스트 상태·수락·완료

잠김/수락 가능은 현재 조건에 따른 가용 상태다. 수락한 퀘스트의 진행 상태와 구분한다.

| 상태 | 의미 | 다음 동작 |
|---|---|---|
| 진행 중 | 현재 회차의 목표 수행 | 목표 갱신, 선택, 실패·포기 정책 적용 |
| 보고 가능 | 목표 조건 충족, 보고/보상 선택 전 | 지정 NPC·현장 보고 또는 정의된 자동 완료 요청 |
| 완료 처리 중 | 보고·선택이 승인되어 완료/지급 확정 중 | 같은 처리 조회·재확인. 새 보상 선택/재수락 금지 |
| 완료 | 해당 회차 완료와 지급 결과 확정 | 후속 해금, 후일담, 반복 가능 여부 계산 |
| 실패/포기 종료 | 해당 회차가 실패·포기로 종료 | 정의된 재시도·재수락 절차. 회차 이력 보존 |

완료 승인 전 현재 소지 등 가변 조건이 미충족되면 보고 가능에서 진행 중으로 돌아가고 부족한 목표를 표시한다. 이미 승인된 완료 처리는 물품 소비 후 소지량이 감소했다는 이유로 되돌리지 않는다.

완료 처리 중에는 포기·회차 종료도 보류한다. 결과 미확정은 실패로 간주하지 않으며 원래 처리를 복구한다. 최종 실패가 확정되면 비용·보상·해금의 처리 결과에 맞춰 재시도 가능한 상태를 정한다. 거절·실패 후 재요청도 같은 논리적 완료 건과 지급 영수증을 대조한다.

자동 완료 퀘스트는 NPC 보고를 생략하지만 동일한 권위 완료 절차를 거친다. 스토리 스킵은 12절의 별도 완료 방식이며, 실제 목표를 수행하거나 던전을 클리어했다고 위조하지 않는다.

수락·포기·보고·보상 선택은 개인 의사와 현재 자격을 확인한다. 관련 의뢰를 출발 화면에서 확인 후 수락할 수 있게 하되, 방장이 다른 사람의 선택·보고를 대신 확정하지 않는다. 일반 질문이나 대화창 닫기를 완료 명령으로 사용하지 않는다.

메인은 추적 해제와 포기를 구분한다. 기본안은 진행을 보존하는 추적 해제이며, 실제 포기 가능 여부는 정의에 명시한다. 서브·반복 의뢰도 포기 시 어떤 목표가 사라지고 퀘스트 전용 물품이 어떻게 처리되는지 보여준다. 영구 해금이나 이미 확정한 보상은 포기로 되돌리거나 재생성하지 않는다.

포기·재수락은 새 실행 회차로 식별하되, 일회성 보상 제한은 퀘스트·캐릭터 또는 명시한 계정 범위에서 유지한다. 회차 번호가 달라졌다는 이유로 최초 보상을 다시 지급하지 않는다. 반복 의뢰의 회차 생성 조건·보상 한도는 별도로 작성한다.

## 6. 목표 구성과 인정 규칙

퀘스트는 목표 묶음과 목표로 구성한다. 묶음은 순차, 모두 달성, 지정한 대안 중 하나의 완료를 표현한다. 목표마다 대상·수량·진행 구간·인정 범위·실패 보존·참여 조건을 작성한다.

| 목표 | 달성 근거 | 작성 시 정할 사항 |
|---|---|---|
| 대화·선택 | 해당 NPC/노드의 승인된 선택 | 개인 확인 필요 여부, 대체 NPC, 접근 조건 |
| 지역 도달·탐색 | 서버가 확인한 구역 진입·발견 | 단순 접근과 완료를 구분, 진입 순서·참여 범위 |
| 조사·오브젝트 조작 | 유효한 대상의 승인된 상호작용 | 개인 조작 또는 공동 조사 결과 인정 |
| 처치 | 승인된 처치 사건과 참여 기록 | 대상 종류/인스턴스, 누적·이번 시도, 막타 불필요 기본안 |
| 획득·소지 | 획득 이력 또는 현재 소유량 | 획득 누적과 현재 소지를 다른 목표로 구분 |
| 물품 전달 | 서버가 확인한 대상 물품의 소비 | 잠금·귀속·수량, 동시 사용/거래 경합, 완료와 소비의 일관성 |
| 호위·방어 | 인스턴스의 구간/생존/시간 조건 달성 | 한 시도 성공 여부, NPC 실패와 재시도 지점 |
| 던전 결과 | 기존 권위 완료·정산 기록 | 해당 콘텐츠·난이도, 성공/실패, 개인 수령 자격 |

현재 소지 목표는 물품을 잃으면 충족 상태가 달라질 수 있다. 보고·완료 승인 시 다시 검사한다. 획득 누적은 이미 승인한 획득을 재조회·재접속으로 중복 계산하지 않는다. 인벤토리 소모품과 화면상 퀘스트 카운터를 혼용하지 않는다.

**순서가 필수인 목표는 앞선 단계가 유효한 상태에서 발생한 사건만 인정한다.** 순서 없는 묶음에서 과거 사건을 모아 달성하게 하려면 수집 시작 시점·유효 범위를 명시한다. 모든 과거 처치와 미수락자의 행동을 자동 소급하지 않는다.

서버 사건에는 대상·발생 ID·캐릭터/파티·콘텐츠·시도·목표 관련 범위를 연결한다. 같은 사건 재전송은 같은 결과로 처리한다. 클라이언트가 보낸 처치 수나 완료 버튼을 달성 증거로 신뢰하지 않는다.

## 7. 실패·재도전와 목표 보존

| 보존 방식 | 예시 | 재도전 결과 |
|---|---|---|
| 개인 영속 성과 | 승인·저장된 단서 발견 | 같은 개인 카운터 재증가 없음. 이번 파티의 물리 사건은 별도 진행 |
| 이번 시도 성과 | 방어 중 생존, 제한 시간 목표 | 새 시도에서 다시 수행 |
| 같은 시도 묶음 | 구출 후 함께 탈출 | 구출만으로 영구 성공 처리하지 않고 탈출까지 성공해야 달성 |

개인 목표 완료로 다음 시도의 문·NPC·적을 생략하지 않는다. 이미 단서를 아는 동료도 다른 참가자의 사건을 함께 수행할 수 있다. 기존 전투 재도전이 보스·Pawn을 복구하는 것과 개인 퀘스트 보존 정책은 별도 연결이다.

실패·포기로 회차를 종료할 때 퀘스트 전용 물품의 유지/회수도 정의한다. 일반 아이템·기존 보상을 임의로 삭제하지 않는다. 실패 재시도가 최초 보상·추첨 결과·획득 카운터를 다시 만드는 경로가 되지 않게 한다.

## 8. NPC·대화·선택지

NPC는 인물 정보, 역할 목록, 상황별 대화 진입점, 개인 표시 조건을 갖는다. 보고/진행/새 의뢰·상점·제작·일반 대화를 함께 탐색할 수 있도록 하며, 하나의 자동 대사가 다른 기능을 가리지 않게 한다.

| 만남 | 시작 방식 | 접근성 |
|---|---|---|
| 첫 만남 | 짧은 인물 소개와 상황 대화 | 이후 질문·의뢰·서비스로 연결. 소개 재감상 가능 |
| 보고 | 보고 대상 하나면 해당 대화, 여러 개면 선택 | 다른 보고·상점·일반 대화로 이동 가능 |
| 반복 방문 | 짧은 인사와 역할 목록 | 추적한 의뢰 강조, 같은 소개 강제 반복 없음 |
| 긴급 사건 | 이동·전투 중 짧은 말과 목표 알림 | 전투 입력을 점유하지 않음. 중요한 선택은 안전 구간 |

대화 노드의 기본 요소는 안정 ID, 화자, 표시 문장, 다음 노드/선택지, 표시 조건, 진행 효과, 선택적 음성·표정·카메라다. 화면 문장은 번역 가능한 텍스트로 작성하고 영속 식별자와 분리한다.

| 선택 종류 | 효과 | 저장 원칙 |
|---|---|---|
| 정보형 | 증언·세계관·상황을 더 물음 | 재열람 상태가 필요할 때만 보존 |
| 태도형 | 말투·인물 반응, 명시한 관계 변화 | 후속 콘텐츠에서 실제 사용하는 결과만 기록 |
| 진행형 | 수락·보고·포기·경로 선택·사건 진행 | 서버가 현재 조건을 재검사하고 승인한 결과 기록 |

표시 당시 가능했던 선택도 실행 전에 조건이 바뀌면 새 상태를 안내한다. 관계 등 영속 상태를 바꾸는 태도형 선택도 진행형과 동일한 서버 조건 확인·승인·중복 처리 방지 규칙을 따른다. 조건 불충족 선택을 숨길지 비활성화할지는 스포일러와 안내 목적에 따라 작성한다. 일반적인 말투 선택으로 예상하지 못한 영구 해금 손실을 만들지 않는다.

개인 관계·편지·후속 의뢰 분기는 개인 기록으로 표현할 수 있다. 경로·구출 대상·보스처럼 모두가 겪는 결과는 공동 사건의 선택으로 명시한다. 개인이 고른 답과 실제 채택된 공동 결과를 혼동하지 않는다. 공동 결과의 결정권·불일치 해결과 영구 분기 제작 범위는 D2다.

공유 공간이 있는 경우 개인 대사·표식은 달라도 공통 통행·충돌은 모순되지 않게 구성한다. NPC 생존·위치·지역 구조가 크게 달라지는 사건은 별도 이야기 공간을 사용하는 안이다. 필수 상점 NPC가 사라진다면 후임·대체 접근 경로를 함께 작성한다.

## 9. 연출·컷신·인스턴스 사건

개인 수동 대화, 전투 중 짧은 대사, 자동 재생 공동 컷신을 다른 실행 유형으로 둔다.

- 개인 대화: 각자 읽고 선택한다. 닫기·일시 중단은 이미 승인한 선택을 취소하거나 다시 실행하지 않는다.
- 짧은 대사: 전투를 멈추지 않는 표시. 발화 순서·동시 표시 제한·다시 확인할 기록을 제공한다.
- 공동 컷신: 준비 후 서버의 사건 시점과 작성된 길이에 맞춰 진행한다. 개인 스킵은 화면 표시만 먼저 종료하고 안전하게 기다린다. 다른 사람의 장면을 끝내거나 전투를 앞당기지 않는다.

공동 컷신은 준비 대상·준비 기한·기한 초과 시 시작/보류/복귀 처리 경로를 작성한다. 준비나 종료 응답을 무기한 기다리지 않는다. 준비·로딩 실패·단절은 기존 입장/복구 규칙과 연결하고 현재 자격을 재확인한다. 준비·재생 실패 자체를 완료 근거로 삼지 않으며, 이미 승인된 개인 성과는 보존한다. 공동 목표 인정은 10절의 참여·멤버십 조건으로 판단한다. 기한 수치는 연출별 실행 계약에서 정하며, 저작된 상영 종료와 별도인 ‘전원 스킵 조기 종료’ 정책은 D3다.

중간 참가자에게 끝난 세계 사건을 다시 실행하지 않는다. 현재 사건 상태를 전달하고 놓친 연출의 개인 다시보기는 세계·퀘스트·보상 효과 없이 제공하는 안이다. 재생되지 못한 음성·카메라 때문에 진행이 영구적으로 막히지 않도록 텍스트·안전한 종료 경로를 작성한다.

인스턴스 사건은 시작 조건, 진행 중 상태, 성공/실패, 정리/재시도를 정의한다. 문 개방·NPC 생성·적 웨이브는 현재 시도의 사건으로 실행하고 재전송·재접속으로 중복 생성하지 않는다. 장면 종료 시 입력·카메라 소유권을 정상 플레이에 돌려준다.

## 10. 파티 목표 인정과 개인 진도

서버는 목표별 참여 사실을 기록한다. 세션·시도·목표와 캐릭터, 참가 시점, 해당 단계 자격, 구역 진입·상호작용·전투 참가 등 목표에 필요한 사실을 사용한다. 피해량이나 막타를 모든 목표의 공통 조건으로 요구하지 않는다.

| 참가 상황 | 진행 인정 기본안 |
|---|---|
| 미완료자와 완료자가 출발 | 미완료자는 자신의 단계, 완료자는 동행·기존 반복 보상 자격 |
| 서로 다른 단계 | 함께 수행 가능한 사건 구간 선택. 개인 완료를 되돌리지 않고 해당 단계에서 진행 |
| 관련 의뢰 미수락 | 출발 전에 안내·본인 수락. 방장이 자동 수락/보고시키지 않음 |
| 전투불능·사망 | 이미 존재하는 목표 참여 기록 보존. 목표의 생존 조건과 기존 자격은 별도 확인 |
| 예기치 않은 단절 | 기존 유예·멤버십과 사건 당시 참여 근거로 판정. 단절을 즉시 포기로 간주하지 않음 |
| 명시적 포기·권한 회수 | 기존 확정 영수증·회수 규칙 적용. 퀘스트가 보상 권한을 되살리지 않음 |
| 실제 중간 참가 | 기존 입장 정책이 허용한 경우에 한해 현재/후속 목표 참여. 과거 참여 근거를 새로 만들지 않음 |

이번 설계가 현재 허용되지 않는 중간 참가를 새로 허용하는 것은 아니다. 재접속 복구와 신규 합류도 구분한다. 목표 참여 기록은 판단 근거이며 그 자체가 보상 권한은 아니다.

단계가 다른 파티에는 ‘조사 진행’, ‘호위 시작 대기’, ‘동행 중’처럼 각자의 상태를 표시한다. 필수 조사를 보완할 수 있는 사건 순서를 제공하고, 조사를 마쳐야 보스 구역이 열리도록 작성할 수 있다. 다만 모든 목표에 모든 사람의 개별 클릭을 강제하지 않는다.

퀘스트 목표마다 인정 가능한 이야기/반복 사건 경로를 지정한다. 출발 화면에서 이번 경로로 진행 가능한 개인 목표를 표시한다. 일반 처치·수집은 정의에 따라 반복 경로에서도 인정할 수 있지만, 구출·호위 사건이 없는 반복 경로의 클리어로 그 사건을 대신 달성시키지 않는다.

## 11. 완료·보상·해금의 일관성

기존 던전 반복 보상과 명시적으로 설계한 퀘스트 최초 보상을 함께 받을 수 있다. **같은 지급 사유를 두 경로가 각각 처리하는 중복**을 막는다. 보상표에는 지급 주체, 사유, 최초/반복, 캐릭터/계정 범위, 선택/확정, 수량·정의 버전을 기록한다.

완료 처리 기본 순서는 다음과 같다.

1. 현재 회차·목표·소유권·선행 조건·요청 버전을 확인한다.
2. 보상 선택과 전달 물품 등 비용을 검증하고 요청 내용을 고정한다.
3. 완료·지급·해금 결과가 전부 반영되거나 안전하게 재개될 수 있는 영속 처리로 확정한다.
4. 확정 결과를 조회해 화면·NPC 반응·다음 퀘스트를 갱신한다.

동일 요청 재시도는 같은 결과를 반환한다. 지급이 미확정이면 ‘확인 중’ 상태로 원래 처리를 재확인하며, 새 요청·다른 보상 선택으로 우회하지 않는다. 완료만 표시하고 보상이 영구 누락되거나 지급만 하고 완료가 풀리는 상태를 만들지 않는다. 한 트랜잭션으로 처리할 수 없는 경계는 영속 작업과 재시도 가능한 확정 절차를 별도 구현 계약으로 설계한다.

기존 던전 정산이 소유한 성장 보상은 해당 경로를 유지한다. 일반 NPC 의뢰까지 던전 클리어 API로 처리하지 않고, 기존 재화·아이템 거래 보장을 재사용할 퀘스트 완료 경계를 마련한다. 새 퀘스트 보상과 기존 성장 지급이 같은 경험치를 다시 지급하지 않게 출처를 구분한다.

보상 아이템은 기존 원칙대로 인벤토리 우선, 초과분은 우편으로 전달한다. 전달 물품 소비·선택 보상·가방 포화는 동일 완료 처리의 일관성 범위에 포함한다. 퀘스트별 자원 수치·경제 밸런스는 별도 콘텐츠 명세다.

## 12. 부캐 스토리 스킵

**확정:** 계정에서 완료한 스토리를 부캐가 선택적으로 건너뛸 수 있다. 성장 점핑은 포함하지 않고, 해당 캐릭터가 적용한 해금과 별도 입장 조건으로 참가 자격을 판단한다.

**설계안:** 챕터 또는 명시한 구간을 스킵 단위로 삼고, 이미 진행한 중간 상태에서도 남은 구간을 처리한다. 적용 전에 아래 내용을 미리 보여준다.

| 항목 | 표시·처리 |
|---|---|
| 자격 | 계정에서 완료한 대상 구간과 현재 캐릭터의 적용 가능 범위 |
| 종료할 진행 | 남은 메인 의뢰, 진행 중인 의뢰와 충돌 여부 |
| 해금 | 지역·던전·NPC 기능·이동 경로 등 이야기 해금 목록 |
| 유지할 성장 | 현재 레벨·SP·스킬 투자·장비. 구간 기준 자동 보정 없음 |
| 보상·비용 | D1/D4 확정 후 실제 지급·미지급·비용을 명시. 미결 상태로 실행 공개하지 않음 |
| 이후 상태 | 다음 메인 시작 위치, 남는 입장 조건, 사건 요약·다시보기 |

직접 완료와 건너뛰기를 구분해 기록한다. 건너뛴 구간은 다음 메인의 이야기 선행 조건을 충족하지만, 실제 처치·퀘스트 보고·컷신 시청을 했다고 기록하지 않는다. 계정의 새 스킵 자격은 직접 완료 근거를 기본으로 하는 안이다. 스킵 기록만 반복해서 이용해 계정 자격 범위를 넓히지 않는다.

챕터별로 ‘스킵 후 도달할 이야기 상태’를 작성한다. 필수 NPC 기능·통로·관련 메인 상태를 빠짐없이 적용하고, 서브 전체를 자동 완료시키지 않는다. 스킵 이후 사라지는 NPC의 서브·관계·선택 결과는 대체 대사·창구 또는 별도 처리로 정의해야 한다. 미해결 개인 분기를 임의의 답으로 완료시키지 않는다. 후속 콘텐츠가 참조할 미선택 분기는 중립 상태·대응 대사·진입점을 작성하거나 D2/D4에서 정한 명시적인 처리로 연결한다. 어느 경로도 없는 구간은 스킵 후 진행 검사에서 거절한다.

동일 스킵 재전송·중간 실패·재로그인은 같은 처리로 복구하며 이미 받은 보상은 재지급하지 않는다. 던전 진행 중이나 완료/보상 처리가 미확정인 상태에서는 진행 변경 충돌을 확인해 적용을 보류한다. 기존 회차를 스킵으로 우회해 보상·비용을 중복 처리하지 않는다.

**기존 성장 연결의 구현 전 조건:** 현재 첫 구간은 완료 이정표에 스킬 해금 등이 연결되어 있다. 스킵을 기존 던전 완료 보고나 성장 완료 함수로 그대로 처리하면 XP·보상·전투 능력까지 따라올 수 있다. 이야기 해금, 전투 습득 자격, 지급을 분리하는 매핑과 기존 캐릭터 호환을 먼저 정의한다. 이 문서는 기존 스킬 해금을 제거하거나 자동 지급하는 결정을 내리지 않는다. D5에서 구체적인 습득 경로를 정하고, 스킵 후 필수 기능을 얻을 방법이 없는 구간은 공개하지 않는다.

스킵 후 별도 입장 조건이 부족한 캐릭터에게는 현재 입장 가능한 반복 콘텐츠와 필요한 성장 경로를 안내한다. 건너뛴 메인을 다시 수행하지 않아도 다음 구간의 기본 조건에 도달할 수 있는지 확인한다. 이는 자동 성장 지급이나 기존 밸런스 수치의 변경 결정이 아니다.

## 13. 저장·재접속·업데이트

영속 대상은 캐릭터 퀘스트 회차·정의 버전·승인 목표·필요한 선택·완료 영수증·개인 해금·계정 자격이다. 대화 타이핑 위치·카메라 프레임·이번 시도의 모든 전투 상태를 영속 퀘스트 기록으로 저장하지 않는다.

목표는 서버가 승인한 의미 있는 변화와 체크포인트에서 저장한다. 화면은 저장 대기와 확정 성과를 구분한다. 서버 장애 시 아직 저장되지 않은 성과까지 복구한다고 보장하지 않으며, 허용할 유실 범위와 저장 시점은 목표별 구현 계약에 남긴다. 기존 장애·재접속 권한 정책은 유지한다.

재접속하면 확정 개인 진도와 현재 인스턴스 사건을 다시 조회한다. 이미 처리한 선택·보상·상호작용을 단순 재생하지 않는다. 정산 중에는 원래 요청을 확인한다. 대화는 유효한 진입점에서 다시 열고, 회상 재생은 진행 효과를 발생시키지 않는다.

제작 데이터의 안정 ID는 문장·행 순서·파일 경로와 분리한다. 오타·번역 수정과 진행 규칙의 버전을 구분한다. 진행 중 퀘스트의 목표 삭제·분기 변경은 구버전 유지 또는 명시적 진도 이전을 제공한다. 완료·스킵·보상 영수증은 패치로 초기화하지 않는다. 퀘스트 이전/삭제 정책 없이 데이터만 덮어쓰는 배포는 거절하는 안이다.

## 14. 데이터와 제작 흐름

| 제작 단위 | 주요 내용 |
|---|---|
| 챕터 | 사건 연결, 핵심 퀘스트, 입장/후속 해금, 스킵 적용 상태 |
| 퀘스트 | ID·버전·종류·수락 조건, 목표 묶음, 보고, 보상, 포기/반복 |
| 목표·묶음 | 대상·수량·순서/대안, 개인/공동 인정, 같은 시도 여부, 보존 |
| NPC | 인물·서비스, 조건별 대화 진입, 개인 표시·대체 접근 |
| 대화 | 노드·번역 문장·화자·선택·조건·효과·선택적 연출 |
| 사건 | 실행 구간·시작 조건·성공/실패·재시도·문/적/NPC/연출 |
| 보상·해금 | 지급 사유/범위/반복·선택, 이야기와 성장 결과의 소유 경계 |

조건은 기존 해금·퀘스트 상태·선택·소유량·입장 조건을 재사용한다. 목표·대화·NPC가 같은 조건을 각각 다른 의미로 구현하지 않도록 공통 판정 규칙을 둔다. 조건은 제한된 조합과 비교로 작성하고, 모든 기획을 임의 코드를 실행하는 범용 언어로 만들지 않는다.

조건의 의미는 ‘이야기 선행 충족(직접 완료 또는 승인된 스킵)’, ‘실제 목표 수행’, ‘보상 수령’, ‘연출 시청’을 구분한다. 다음 메인의 이야기 선행 조건에 실제 수행·시청 조건을 잘못 사용해 스킵이 무효가 되는지 검사한다. 의도적으로 실제 수행이 필요한 콘텐츠는 별도 조건과 습득 경로를 명시한다.

UE 구조화 에셋과 대량 대사 표 편집을 함께 사용하는 안이다. 정의 원본에서 서버 판정용 목록과 클라이언트 표시용 데이터를 생성해 수작업 이중 작성을 피한다. 구체 클래스·DB 스키마·HTTP API는 구현 설계 단계에서 결정하며 이 문서가 새 API의 존재를 보장하지 않는다.

제작 순서는 **사건·해금 관계 → 퀘스트/목표 → 인정·실패 정책 → NPC/대화/사건 연결 → 보상·스킵 → 미리보기·검사**다. 자주 쓰는 정책은 검토된 템플릿으로 재사용하고 예외를 눈에 보이게 작성한다.

필수 검사 항목은 중복/누락 ID, 없는 대상, 막힌 필수 진행, 해금 순환, 보상 사유 충돌, 미지정 목표 보존 정책, 끝나지 않는 연출, 스킵 후 필수 기능 누락이다. 미리보기는 신규·진행 중·완료·스킵 캐릭터와 다른 진도의 파티를 지원한다.

## 16. 설명용 챕터: 폐광의 실종자

아래 이름·ID·이야기는 **설계 점검용 가상 콘텐츠**다. 실제 세계관·출시 챕터를 확정하거나 기존 훈련/입문 콘텐츠를 대체하지 않는다. 각 의뢰 보상 수치는 별도이며, 스킵 보상은 D1이다.

| 예시 ID | 흐름/목표 | 사건·대화 | 완료 결과 |
|---|---|---|---|
| EX.M01 | 마을에서 운송 중단 조사 의뢰 수락 | 주민과 상인의 증언. 추가 질문은 선택 | 외곽 조사 목표 활성 |
| EX.M02 | 외곽 흔적 조사 | 개인/공동 인정이 명시된 단서 3개. 문양 발견 | **폐광 입장 해금**, 구출 의뢰 제시 |
| EX.M03 | 폐광 내부 조사·생존자 발견·구출 | 내부 조사 후 구역 개방. 생존자 대화 | 같은 시도 호위 목표 활성 |
| EX.M04 | 생존자 호위·방어·탈출 확보 | 적 웨이브와 출구 개방. 구출부터 같은 시도 묶음 | 결전 구간 진행 가능 |
| EX.M05 | 보스 처치·귀환 보고 | 보스 사건 종료 후 개인 보고·명시된 최초 보상 | 챕터 해결·다음 지역 해금 |
| EX.S01 | 실종자의 유품 조사 | 생존자의 가족과 별도 이야기 | 선택 보상·후일담. 메인 필수 아님 |
| EX.R01 | 해금 후 폐광 반복 | 저자가 지정한 반복용 사건 구성·목적 안내·기존 던전 보상 | 메인 최초 보상·보고 반복 없음 |

EX.M03~M04는 설명상 여러 의뢰로 표시했지만, ‘구출 후 탈출’을 같은 시도에 요구하는 실제 작성에서는 하나의 목표 묶음 또는 명시적 시도 연결을 사용한다. 구출만 개인 영속 성공으로 남겨 다음 시도의 호위 사건을 건너뛰지 않는다.

같은 폐광에 A(EX.M03 내부 조사부터), B(메인 완료), C(개인 호위 단계)가 참가하면 출발 시 조사→구출→호위→보스 구간을 선택한다. A도 EX.M02를 완료해 폐광 해금과 입장 조건을 충족한 상태다. A는 내부 조사 진행, C는 호위 대기, B는 동행을 본다. C도 새 시도에서는 생존자 발견·구출을 함께 수행하고 이번 시도의 참여·선행 조건이 성립한 뒤 호위·탈출을 인정한다. 이전 시도의 개인 단계 표시로 같은 시도 조건을 대체하지 않는다. 공동 조사로 문이 열리고 B가 보스를 먼저 잡아 A의 필수 사건을 없앨 수 없도록 사건 순서를 작성한다.

EX.R01의 반복 구성은 최초 이야기 구성과 다를 수 있으나 저자가 명시한 경로로 선택한다. 혼합 진도 파티가 이야기 구간을 선택했다면 완료자의 개인 기록으로 공동 사건을 생략하지 않는다. 반복 구성에 없는 구출·호위는 해당 경로에서 메인 목표로 인정하지 않고 출발 전에 안내한다.

개인 보고를 아직 하지 않은 A와 보고가 끝난 C에게는 마을 NPC 대사가 다르다. 상점 등 공통 기능은 둘 다 접근 가능한 목록에서 찾을 수 있다. 계정에서 이 챕터를 완료한 뒤 부캐가 스킵하면 지정한 이야기 해금을 얻지만 레벨·장비는 그대로이며, 던전의 별도 조건이 부족하면 이유를 표시한다.

## 17. 사례별 설계 점검 기준

아래는 구현 후 확인할 인수 조건이며, 이번 문서 작성으로 테스트가 통과했다는 뜻은 아니다.

| 사례 | 기대 결과 |
|---|---|
| 초행 단독 진행 | 안내만으로 수락·행동 이유·목표·보고·다음 구간을 이해하고 해금 순환 없이 진행 |
| 초행+완료자 | 최초 경험/개인 선택 보존, 공동 전투 가능, 최초 보상 재지급 없음 |
| 다른 단계의 파티 | 출발 전 진행 적합성 표시, 공통 구간 선택, 개인 이전 진도 보존 |
| 미해금 파티원 | 출발/입장에서 개인 조건 거절, 방장 해금으로 우회 불가 |
| 의뢰 미수락 | 출발 전 안내·본인 수락. 사후의 이해할 수 없는 불인정 최소화 |
| 순서 없는 목표/필수 순서 | 정의한 수집 시작·선행 규칙대로만 인정, 늦은 이벤트로 단계 건너뛰기 없음 |
| 동일 처치·선택 재전송 | 목표·보상·세계 생성 1회 효과 유지 |
| 보고 가능 중 목표 물품 소실 | 완료 승인 전에는 진행 중으로 복귀·부족량 안내, 승인 후 정상 소비를 미달로 오인하지 않음 |
| 완료 미확정 중 포기 | 포기·회차 종료 보류, 원래 처리 복구, 비용/보상/해금 중복 없음 |
| 이야기/반복 경로 차이 | 경로별 인정 가능한 목표 표시, 존재하지 않는 구출·호위의 대리 완료 없음 |
| 실패 후 재도전 | 영속 단서와 이번 시도 구출·탈출을 구분, 개인 완료로 세계 사건 생략 없음 |
| 사망·단절·재접속 | 기존 참여/멤버십과 목표 조건대로 판단, 승인 기록 복원·보상 중복 없음 |
| 보상 응답 유실·가방 포화 | 원래 완료 처리 확인, 보상 선택 고정, 기존 가방 우선/초과 우편 보장 |
| 공동 컷신·개인 스킵 | 초행 장면 강제 종료·스킵자 조기 전투 없음, 무한 대기 없음 |
| NPC에 여러 의뢰 | 보고·새 의뢰·상점이 다른 대사에 가려지지 않음 |
| 부캐 중간 진도 스킵 | 미리 본 결과대로 메인/해금 연결, 기존 보상 재지급·성장 점핑 없음 |
| 스킵 후 레벨·전투 기능 부족 | 현재 이용 가능한 성장·습득 경로 안내, 메인 재수행 강제 없이 기본 조건 도달 가능 |
| 스킵 뒤 직접 재감상 | 세계·개인 선택·보상 재실행 없이 이야기 확인 |
| 콘텐츠 패치 | 기존 진행 이전/구버전 유지, 완료·스킵 영수증 보존 |

2026-11-03 문서 작성 중 아래 소스의 해당 부분을 읽었다. Blueprint 전체나 실제 실행을 감사한 결과가 아니며, 공통 퀘스트 기능 전체의 부재/완료를 단정하지 않는다.

이 문서 작성은 구현 착수·기존 데이터 이전·스킵 공개·공유 파일 변경 권한의 확장이 아니다. 후속 구현은 최신 예약·실제 호출 코드를 확인하고 기능별로 진행한다.

## 19. 제작·구현 단계안

| 단계 | 결과물 | 해당 단계의 완료 기준 |
|---|---|---|
| 1. 기획 통합 | 본 문서, 미결 목록, 대표 챕터와 사례 | 확정/설계안 구분, 6인 검토, 모순·미정 의존성 표시 |
| 2. 정의·기록 기반 | 퀘스트/목표/대화/조건 정의와 개인 기록, 저작 검사 | 안정 ID·버전, 수락·진행·복원, 기존 성장/보상 소유권 계약 |
| 3. 개인 플레이 연결 | NPC 의뢰→조사/처치→보고·보상→해금, 목록/HUD | 정상 흐름·실패·응답 유실과 보상 일관성 확인 |
| 4. 파티 사건 연결 | 혼합 진도, 참여 인정, 사건·연출 | 개인 조건·공동 순서·단절/재접속·스킵 경계 확인 |
| 5. 부캐 스킵·패치 호환 | 대상 구간 스킵·이전 상태 처리·미리보기 | D1/D4/D5와 분기 대상의 D2 결정 후 성장 점핑 없는 완결된 이야기 해금 |
| 6. 콘텐츠 제작 확대 | 실제 시나리오·NPC·퀘스트·연출 | 목표별 정책 작성과 플레이 점검, 반복 제작 가능한 작업 흐름 |

위 순서는 설계 제안이다. 제한된 첫 구현으로 전체 목표 유형 지원을 완료했다고 표시하지 않는다. 이번 요청의 완료 단위는 **검토된 기획 초안 작성**이며 2~6단계 구현은 포함하지 않는다.

## 20. 후속 결정 목록

기본 해금·권위·중복 방지 규칙을 다시 선택지로 묻지 않는다. 아래 사항만 관련 콘텐츠/기능의 구현 계약을 확정하기 전에 결정한다.

| ID | 미결 사항 | 권고·대안 | 결정이 필요한 시점 |
|---|---|---|---|
| D1 | 스토리 스킵 시 원래 퀘스트 XP·재화·물품·선택 보상 | 지급/미지급/종류별 정책을 명시. 성장 점핑과 별개. 이미 받은 보상 재지급 금지 | 스킵의 경제·완료 계약 |
| D2 | 영구 개인 분기 범위와 공동 사건 선택 결정권 | 인물 반응/국소 분기 기본안. 공동 결과는 명시적 결정 구간, 방장·투표 등 정책 선택 | 분기 콘텐츠 저작·저장 형식 |
| D3 | 공동 컷신의 전원 스킵 조기 종료·초행 보호 | 개인 스킵/안전 대기 기본안. 조기 종료는 별도 합의 | 공동 연출 공개 |
| D4 | 부캐 스킵 적용 단위·시점·비용 | 챕터 단위·중간 진도 지원 권고. 비용 유무·수치 미확정 | 스킵 UI/서비스 공개 |
| D5 | 스토리 스킵과 기존 성장·전투 스킬 습득 자격의 연결 | 이야기 해금과 성장 지급 분리. 현재 입장 가능한 성장 경로·필수 전투 기능의 독립 습득·기존 캐릭터 호환 필요 | 성장·입장 통합 및 스킵 공개 |
| D6 | 실제 세계관·챕터 분량·NPC·목표·보상 수치 | 16절은 설명용. 실제 첫 챕터를 선정하고 기존 훈련·입문과 연결 | 실제 콘텐츠 제작 |

공통 기반의 설계 검토는 진행할 수 있지만, 미결 정책에 임의 기본값을 넣어 해당 기능을 운영 공개하거나 완료 처리하지 않는다. 이 문서를 게시해도 D 항목이 사용자 승인으로 바뀌지 않는다.

## 21. 팀 검토와 문서 확인

참여는 시스템 기획 3명(퀘스트 상태·멀티플레이·저작 구조)과 콘텐츠 기획 3명(시나리오·대화·퀘스트 경험)이다. 앞선 역할별 제안·교차 검토를 통합한 초안을 6명이 실제 팀 에이전트로 읽고 검토했다. 아래 지적을 진행자가 문서에 반영했다. 이는 문서 검토이며 런타임 기능 통과나 미결 정책의 사용자 승인이 아니다.

| 담당 | 본문 최종 검토 | 반영 내용 |
|---|---|---|
| 시스템: 퀘스트 상태 | 검토 완료·보완 반영 | 가변 조건의 보고 가능 되돌림, 완료 미확정 포기 보류, 혼합 진도 예시의 시도 연결 |
| 시스템: 멀티플레이 | 검토 완료·보완 반영 | 컷신 준비 기한/처리, 재생 실패와 기승인 성과 구분, C의 같은 시도 구출 조건 |
| 시스템: 저작 구조 | 검토 완료·보완 반영 | 이야기 선행/실제 수행/지급/시청 조건 구분, 스킵의 미선택 분기 대응 검사 |
| 콘텐츠: 시나리오 | 검토 완료·보완 반영 | 고정 정의와 나중에 선택할 결과 구분, 반복 사건 경로, 스킵의 D2 의존성 |
| 콘텐츠: 대화·연출 | 검토 완료·보완 반영 | 공동 분기 확정 시점, 영속 관계 선택의 서버 승인, NPC 기능 접근·연출 수명 확인 |
| 콘텐츠: 퀘스트 경험 | 검토 완료·보완 반영 | 스킵 후 독립 성장 경로 안내, 이야기/반복 경로별 목표 인정 |

문서 확인 항목은 사용자 합의 대조, 예시의 진행·해금 관계, 상태/보상/스킵 모순, 상대 링크, 변경 범위다. 게임 빌드·런타임 검증을 문서 확인 결과로 대체하지 않는다.
