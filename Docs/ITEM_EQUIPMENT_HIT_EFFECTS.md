# 장비의 승인 적중 효과

## 범위와 상태

첫 구간 인내·순환 대검의 공통 확장 경로다. 기존 장비 저장/장착·성장·제작·이전과 서버의 승인 피해/직업 권한은 재사용한다. 첫 구간 성장 표의 UE/backend 코드 등록은 이번 변경에서 이관하지 않는다.

공통 효과 경로와 두 대검의 실제 Definition 연결을 구현하고 설치했다. 효과 종류별 능력을 재사용하며 스킬에 아이템 ID 분기를 추가하지 않는다. 검증 범위와 빌드의 한계는 아래에 기록한다.

## 책임과 확장

- `URPGItemDefinition`의 장착 Fragment는 기존 AbilitySet을 통해 효과 능력을 부여하고 회수한다.
- `URPGItemShieldOnHitDefinitionFragment`와 `URPGItemResolveOnHitDefinitionFragment`는 필요한 스킬 태그·완충/마무리 조건·효과 수치만 저작한다. World·UI·인벤토리를 직접 변경하지 않는다.
- SkillContainer는 서버 승인 피해 뒤 `URPGApprovedSkillHitEvent`를 동기 발행한다. 데이터는 해당 native 경로만 작성하며, 클라이언트 RPC·Blueprint 성공 보고를 발동 자격으로 사용하지 않는다.
- `URPGEquipmentHitAbility`는 현재 장비의 실제 부여 핸들·ItemId·Definition 버전·부여 수명·활성 장착 세대를 확인하고 같은 시전에 한 번만 발동한다. 같은 Definition의 복제본이 다른 슬롯에 있어도 다른 아이템의 부여 핸들은 보상받지 않는다.
- 보호막 능력은 공통 `URPGShieldComponent`에 자신의 출처만 등록/해제한다. 자원 능력은 기존 직업의 투지 변경 경로와 습득·폭주·서버 권한 검사를 재사용한다.
- 피해 처리는 아이템 ID를 알지 못한다. 최종 TakeDamage 중 보호막이 흡수하지 못한 부분만 체력에서 차감하며, 직접 체력 변경이나 체력 소모에는 관여하지 않는다.

새로운 수치/조건의 동일 종류 효과는 Fragment 데이터로 저작한다. 새로운 동작은 효과 Ability를 확장하며, SkillContainer에 아이템별 분기를 추가하지 않는다. 장비로 새 AbilitySet을 부여하는 기존 동작과 백엔드의 정확한 정의/버전 허용 목록을 유지한다.

## 첫 두 효과의 규칙

| 설정 | 인내 | 순환 |
|---|---|---|
| 스킬 태그 | `Player.Ability.Skill.Charge` | `Player.Ability.Skill.WhirlWind` |
| 필수 조건 | 서버 승인 유효 적중과 최대 차지 해제 | 서버 승인 정상 마무리 유효 적중 |
| 수치 | 최대 체력 5%, 3초 | 기존 기본 수급과 별개로 투지 +20 |
| 같은 시전 | 다단·다수 적중에도 한 번 | 다단·다수 적중에도 한 번 |
| 다른 시전 | 새 양으로 교체하고 3초 갱신, 가산 없음 | 별도 한 번, 기존 투지 상한 적용 |
| 폭주 | 완충 조건을 충족하면 발동 | 폭주에서 승인된 마지막 시전까지 수급 금지 |

두 효과 모두 +0부터 같은 조건/수치로 작동하며 제작품·드롭품에 차이를 두지 않는다. 최대 체력 성장으로 인내의 실제 양이 늘어나는 것은 비율 증가와 구분한다. 이 수치들은 첫 플레이 비교값이며 고강화의 추가 해금이 아니다.

순환을 위해 별도 최소 유지 시간이나 타이머를 추가하지 않는다. 현재 실행 정책이 정상 마무리 진입을 인정하고 그 마무리 타격이 실제 승인돼야 한다. `EndAbility` 호출만으로 보상하지 않는다. 초과 투지는 보관하거나 폭주 후 환급하지 않는다.

## 보호막과 수명

- 발동 시 최대 체력으로 양을 정한다. 최대 체력 증가로 보충하지 않으며 감소 시 잔량을 새 최대치의 같은 비율 이하로 낮춘다. 증가로 돌아와도 잃은 잔량/시간을 되살리지 않는다.
- 생성 전에 처리된 피해를 소급해서 막지 않는다. 만료 후 피해를 흡수하지 않으며 일반 무적/강제 사망 규칙을 바꾸지 않는다.
- 무기 해제·활성 세트 전환은 그 능력이 소유한 보호막을 회수한다. 되돌려 장착해도 이전 시전의 자격은 복구되지 않는다.
- 사망·전투 수명 회수·Pawn 교체에서 제거하며 이전 Pawn/이전 시전의 늦은 적중은 거절한다. 이미 정상 지급한 투지는 장비 효과가 임의로 소급 회수하지 않고 기존 직업 수명 규칙을 따른다.
- 일시 보호막을 ItemRecord/DB·강화 이전에 저장하지 않는다. 동일 서버 Pawn의 재접속은 원래 잔여 상태/만료 시간을 따르고 새 Pawn에는 이월하거나 재지급하지 않는다.
- OwnerOnly 보호막 잔량/서버 만료 시각과 Blueprint 조회·변경 이벤트를 제공한다. 체력 회복과 구분하며 소유자 HUD 연결은 아래 후속 절을 따른다.

## 저작과 확인

`Scripts/Editor/ConfigureEquipmentHitEffects.py`는 기본 읽기 전용이다. `-RPGEquipmentHitEffectsApply`에서만 기존 대검 2개와 새 AbilitySet 2개를 연결한다. 소유 아이템 지급·DB 변경·옵션 추첨·전투 상태 주입을 하지 않는다. 전용 사본에서 작성/새 프로세스 재로드 후 원본 해시를 확인해 예약한 4개 에셋만 설치한다.

유지할 직접 회귀는 `ProjectRPG.Item.EquipmentHitEffects`이다. 보호막의 실제 GE 피해 흡수·갱신·최대 체력·만료·사망과, 실제 서버 승인 피해에서의 데이터 기반 발동·부여 수명·중복/위조 거절을 확인한다. 순환은 실제 클래스/습득/편성 상태의 native 마무리 확인 fixture로 기본 수급과 별도의 상한·마지막 폭주 시전 금지를 확인한다. 실제 네트워크·물리 입력·자연 전투의 입증으로 확대하지 않는다.

- 최종 DLL SHA256은 `46B04A266F374042A354C880A0789CE8BF3E3FD068B80F2C2BAB715F325B1783`이다. 동일 DLL을 실제 로드한 별도 Cmd 4개에서 효과 저작, 새 프로세스 읽기 전용 재로드, 기존 장비 작성기의 7개 Definition 읽기 검증, native 8개를 모두 종료0으로 확인했다. 기존 작성기는 추가 저장0·누락0·각 정의 Valid이며 두 효과도 인식한다.
- native는 신규 `ApprovedDispatchAndOwnership`·`ResolveClassGateAndFinalBerserk`·`ShieldLifecycle` 3개와 기존 장비 성장 4개·대검 폭주 수명1개, 총8개 모두 Success다. 탐색 전 기존 엔진 기동 Error15줄과 탐색 이후 Error0을 구분한다. 실제 순환 검사 월드는 GameInstance 없는 native fixture로 장착 무기 액터만 명시적으로 연결하며, 마무리 확인도 native fixture다. 비동기 액터 로딩·자연 몽타주 적중·Iris·Steam·GPU/HUD 외형의 증거는 아니다.
- 사본 검증 뒤 원본 기준 해시를 재확인하고 기존 대검2/새 AbilitySet2만 설치했다. 원본의 네 파일은 검증 사본의 SHA와 일치한다. 원래 대검 템플릿·다른 아이템·DB·설정은 변경하지 않았다.

## 소유자 보호막 HUD 연결 — 2026-11-03

기존 체력 모듈 위에 `URPGPlayerShieldWidget`을 독립 자식으로 붙인다. `보호막 +잔량`과 남은 초를 청록색으로 표시하며, HP/MP 값·체력 바·디버프 행은 바꾸지 않는다. 원본 Vitals WBP만 작성하고 부모 HUD나 공용 상태바 템플릿은 저장하지 않는다.

플레이어는 빈 `URPGShieldComponent`를 기본 컴포넌트로 갖는다. HUD가 첫 적중 전에 구독할 수 있으며, 아직 보호막이 없는 상태에서는 값을 지급하거나 표시하지 않는다. 다른 액터의 기존 지연 생성 경로는 유지한다. 보호막 수치의 복제는 기존 OwnerOnly 상태를 사용한다.

표시는 장비 이름·아이템 ID·발동 조건을 모른다. 보호막/체력 이벤트와 소유 Pawn 교체를 구독하고 해제하며, 보이는 동안에만 0.1초 간격으로 표시 시간을 갱신한다. 만료 시각은 GameState의 서버 시각과 비교한다. 늦게 도착한 만료 상태가 시간을 다시 시작하게 만들지 않으며 UI에서 보호막 상태를 수정하지 않는다. 보호막0·기한 경과·사망·소유 Pawn 없음·위젯 제거 때 숨기고, 소유 플레이어가 있는 위젯에는 다른 Pawn을 명시적으로 연결해도 표시하지 않는다.
