# 협동 세션의 지역 이동

프로젝트 전투 테스트 지형에서 확인하려면 `/Game/Maps/RegionTravel/L_RegionTravelTest`를 연다. `testmap`을 기반으로 만든 이 맵에서는 기본 시작 지점 정면 약 7m에 두 기둥과 가로대가 보인다. 기둥 사이를 지나면 `L_Field`로 이동한다. 필드의 문으로 되돌아가면 테스트 맵의 입구 앞으로 나온다. 에디터의 Play As Client에서 플레이어 수를 2로 설정하면 두 번째 플레이어를 출발지에 둔 채 왕복을 확인할 수 있다.

에디터에서 `/Game/Maps/RegionTravel/L_Town`을 열고 플레이한다. 마을 광장의 두 기둥 사이로 들어가면 필드로 이동하고, 필드의 문으로 되돌아가면 마을로 귀환한다. 두 명으로 플레이할 때 각 플레이어가 독립적으로 이동한다.

## 지역 연결

- 시작 지역은 퍼시스턴트 레벨이다. 필드는 같은 월드의 Blueprint 스트리밍 서브레벨로 추가하고 Initially Loaded와 Initially Visible을 끈다. World Settings의 Use Client Side Level Streaming Volumes를 켜서 늦게 접속한 플레이어도 시작 지역에서 출발하도록 한다. 통로가 관리하는 서브레벨에는 별도 스트리밍 볼륨을 두지 않는다.
- 퍼시스턴트 레벨에 `RPGRegionGate` 두 개를 배치한다. 각 문의 Region Level에 **문이 서 있는 지역**을 지정한다. 시작 지역은 비워 둔다. 각 문의 Destination을 상대편 문으로 지정하면 왕복 통로가 된다.
- Arrival 화살표는 캐릭터 캡슐 중심이 놓일 위치와 방향이다. 평평한 바닥 위, 문 트리거와 벽 바깥에 둔다. 지역은 서로 겹치지 않는 월드 좌표에 배치한다. 서브레벨 속의 액터는 해당 레벨의 네트워크 가시성을 사용하고, 퍼시스턴트 레벨의 동적 액터에는 기존 네트워크 관련성 설정이 적용된다.

## 전환 수명

서버의 트리거가 소유 캐릭터·출발 지역·진행 중 요청을 확인한다. 컨트롤러의 RegionTravel 컴포넌트가 이동 번호를 발급하고 이동과 `Player.Ability` 태그의 신규 GAS 능력 발동을 잠근다. 목적지 로딩을 요청한 클라이언트는 개인 로딩 화면과 입력 차단을 적용한다.

클라이언트가 목적지 레벨 표시를 확인해 같은 번호로 응답하고 서버에도 목적지가 준비되면, 서버가 같은 캐릭터를 Arrival로 이동시킨다. 서버의 `GetCurrentRegion`은 성공한 목적지 레벨 패키지를 반환한다. 시작 지역과 새로 빙의된 캐릭터의 기본값은 None이다. 서버는 방문한 레벨을 유지하고, 원격 클라이언트는 도착 위치 동기화 후 이전 서브레벨을 해제한다. 리슨 서버 호스트는 서버 월드를 공유한다.

준비 중 빙의 변경, 출발 트리거 이탈, 30초 초과, 배치 실패 시 이동을 취소하고 잠금을 해제한다. 이미 확정한 이동은 되돌리지 않는다. 클라이언트의 도착 위치 확인에는 5초의 화면 복구 상한이 있다.

전환 취소 후 해당 플레이어의 로딩 화면을 닫고 HUD에 사유와 재시도 방법을 표시한다. 목적지 준비 시간 초과, 도착 지점 배치 실패, 출발 조건 변경을 구분한다. 빙의 변경 등으로 HUD 알림이 연결되지 않은 순간에는 같은 플레이어 화면에 임시 안내를 표시하며, 추가 확인 입력 없이 다시 이동할 수 있다.
