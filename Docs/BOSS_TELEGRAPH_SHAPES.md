# 보스 공격 범위 데칼의 형상 연결

기존 보스 예고 데칼은 Style의 반경과 원형 마스크만 사용했다. 서버 HitQuery의 부채꼴,
안쪽 안전지대, 방향과 다른 크기를 표현할 수 없었다.

이번 연결은 공격이 확정한 HitQuery 형상/변환을 서버 예고 스냅샷에 함께 보존한다.
클라이언트는 그 값으로 지면 표시를 구성하며, 실제 피해는 기존 서버 HitQuery/GAS가 결정한다.
중도 참가도 서버 시작/종료 시각과 최신 형상을 읽고 동일한 진행도를 복원한다.

지원 표시는 원(Sphere/수직 Capsule의 수평 범위), 박스, 부채꼴, 고리형 부채꼴/도넛,
둥근 끝을 갖는 직선 Sweep이다. 도넛은 RingSector의 각도 360도와 안쪽/바깥 반경을 사용한다.
데칼은 지면의 수평 범위를 안내하며 공중의 높이 조건까지 표현하는 3D 볼륨은 아니다.

기존 원형 머티리얼의 색상/진행도 파라미터는 유지한다. 새 형상 사용을 켜지 않는 기존
지속 장판/소환 등의 표현은 종전 UV 원형 마스크를 계속 사용한다. 작성기는 기본 검증 전용이고
`-RPGBossTelegraphShapesApply`에서만 해당 머티리얼 한 개를 변경한다.

공격 데이터 작성:

- `RPGBossTelegraphedStrikeAbility` 파생 GA에서 `bUseCustomHitShape`를 켜고 `HitShape`를 설정한다.
  전방 부채꼴은 `Sector`, 고리/도넛은 `RingSector`를 사용한다. `AngleDegrees=360`이면 완전한 도넛이다.
- `Radius`는 바깥 반경, `InnerRadius`는 고리 안쪽 안전 반경이다. `AngleDegrees`는 전체 각도다.
  `HalfHeight`는 실제 서버 충돌 판정의 높이다. 박스는 `BoxHalfExtent`, 직선은 `Length`와 `Radius`를 쓴다.
- 보스 중심 공격은 `bCenterHitShapeOnSource=true`, 타깃 위치에 떨어지는 공격은 기본값 false를 쓴다.
  방향은 시전 시작 때 타깃을 향한 수평 회전으로 고정한다. `LocalOffset`/`LocalRotation`도 반영한다.
- 여러 참가자를 맞히려면 기존 `bHitAllThreatParticipants`를 켠다. 대상 수/적대 관계/참가 자격은
  기존 서버 보안 프로필과 위협 목록 규칙을 따른다. 형상 설정 자체가 피해 권한을 추가하지 않는다.
- 별도 GA는 `StartBossTelegraphForHitQuery`에 실제 피해에 사용할 고정 Transform/Profile을 전달한다.
  직접 호출하는 경우 `BeginTelegraphWithShape` 역시 서버 권한과 현재 전투/예고 수명 검사를 거친다.

Strike는 예고 시작 전에 형상과 좌표를 복사하고 실제 타격에도 같은 복사본을 사용한다.
시전 중 보스 이동이나 GA 기본값 변경으로 예고와 타격 범위가 달라지지 않는다.
기존 Strike 에셋은 `bUseCustomHitShape=false`로 기존 Sphere/Radius를 유지한다.
Dash는 확정한 전체 이동 경로의 둥근 직선 범위, 장판 시전 예고는 실제 장판 반경을 전달한다.
기존 GA 에셋을 임의로 부채꼴/도넛으로 바꾸거나 밸런스를 변경하지 않는다.

지면 표시는 수평 형상만 허용한다. 기울어진 형상, 잘못된 반경/각도, 지나치게 큰 범위는 시작을 거절한다.
지원 파라미터가 없는 다른 원형 머티리얼로 새 형상을 대신 그리지 않는다. Style에는 형상 지원
`M_RaidSwordManTelegraph` 또는 같은 파라미터 계약의 데칼 머티리얼을 지정해야 한다.
취소/리셋/사망 시 예고와 형상을 함께 비우며, 새 예고의 Sequence/Encounter가 이전 콜백을 차단한다.
