# 혼자 사용하는 로컬 레이드 테스트

프로젝트 루트 PowerShell에서 실행한다. 현재 소스로 정상 `Project_RPGEditor` 빌드가 필요하다.

```powershell
.\Scripts\Start-SoloRaid.ps1
```

기본 구성은 **직접 조작할 게임 창 하나 + 봇 클라이언트 세 개 + 전용 서버 하나**다. 보조 프로세스는 숨겨 실행한다. 모든 캐릭터는 실제 네트워크 플레이어이며 정상 이동·공격 입력과 서버 피해 판정을 사용한다. Steam, 백엔드, 다른 계정은 필요 없다.

준비가 끝나면 게임 안에 지휘 패널이 열린다. 공격을 누르고 F8로 닫으면 평소처럼 내 캐릭터를 조작할 수 있다. 내 캐릭터의 이동·공격은 자동화하지 않는다.

| 게임 키 | 동작 |
|---|---|
| F8 | 지휘 패널 열기/닫기. 열린 동안 내 캐릭터의 이동·시점 입력을 잠근다. |
| F5 | 봇 공격. 현재 소환 기믹에서는 살아 있는 수호자를 우선 공격한다. |
| F6 | 봇 전체 대기. 보스와 기믹 제한 시간은 계속 진행된다. |
| F7 | 내 캐릭터 주변으로 집결. 공격 중단. |
| F9 | 보스 주변 약 6m로 산개. 공격 중단. |
| F10 | 기존 재시작 경로로 보스·파티를 복구하고 준비 상태로 돌아간다. F5로 재개. |

패널은 각 캐릭터의 HP·행동, 보스 HP·결과, 소환 기믹의 처치 수·남은 시간을 표시한다. 응답이 끊긴 클라이언트는 대기/응답 없음으로 표시한다. 종료 버튼 또는 정상적인 사람 창 종료 시 실행기가 자기 서버·클라이언트를 종료하고 임시 데이터를 정리한다.

봇마다 다음 정책을 선택한다. 전체 명령이 공격이어도 개별 대기 봇은 움직이거나 공격하지 않는다.

| 정책 | 용도 |
|---|---|
| 자동 참여 | 현재 소환몹·보스 공격, 보스 예고·장판에서 기본 회피 |
| 이 봇 대기 | 파티원 일부가 행동하지 않는 상황 |
| 기믹 무시 | 소환몹 대신 보스를 계속 공격. 무적 기믹 제한 시간 초과 재현 |
| 회피 끄기 | 기믹에는 참여하지만 예고·장판 회피는 하지 않음 |

기믹 실패를 반복하려면 F5로 기믹까지 진행한 뒤, 세 봇 모두 대기시키고 내가 소환몹을 처치하지 않는다. 실제 기믹 제한 시간으로 실패한다. 기믹 무시는 보스 공격을 계속하므로 넓은 공격에 근처 소환몹이 우연히 맞을 수 있다. F10 재시작 → 봇 자동 참여 → F5 순서로 재도전한다. 소환 대상은 현재 encounter·phase·sequence에 속하고 초기화된 적의 살아 있는 기록만 사용한다.

## 지원 범위

- `/Game/Maps/bossmap`의 현재 레이드를 대상으로 한다. 원본 맵·보스 에셋·기믹 체력과 제한 시간은 변경하지 않는다.
- 빈 개발용 장비 상태에만 대검을 메모리로 지급한다. 기존 장비를 덮어쓰거나 실제 인벤토리·보상을 저장하지 않는다.
- 봇은 Enhanced Input 이동·기본 공격을 사용한다. HP 감소, 직접 피해 적용, 기믹 완료 상태 주입은 하지 않는다.
- 회피는 현재 복제된 보스의 예고·장판 지면 범위를 읽어 바깥으로 이동하는 최소 행동이다. 범용 길찾기, 모든 일반 몬스터의 공격 예측, 힐러·탱커 역할 AI는 아니다. 산개는 재현용 배치다.
- 시작/재시작 준비 중에는 보스 AI를 멈춘다. 세션 전체 전투 제한은 준비를 위해 30분이지만, 소환 기믹 자체의 제한 시간은 유지한다.
- 개발 재시작은 현재 참가자 Pawn을 정리해 기존 `RestartPlayerAtTransform` 복구 경로에서 입장 위치에 다시 생성한다. 전투 중 멀리 밀려나거나 낙하한 참가자도 복구하며, 새 Pawn의 장비·입력 준비를 기다린다. 봇은 이동하려는 바로 앞의 바닥이 없으면 걸음을 멈춘다.
- 실제 로그인·파티 초대·입장권·백엔드 정산·Steam·다중 PC 검증은 별도다.
- 일반 실행과 Shipping에서는 활성화하지 않는다. 명시적 개발 플래그, 프로젝트 `Saved/SoloRaid` 내부 제어 파일, 백엔드 세션 자격 없음이 필요하다. 서버는 루프백에만 바인딩한다.

## 실행 옵션과 자동 확인

```powershell
# 인원 축소 / 보조 화면 관찰
.\Scripts\Start-SoloRaid.ps1 -Players 2
.\Scripts\Start-SoloRaid.ps1 -ShowBots

# 전원 봇: 기본 공격·대기·산개·재시작
.\Scripts\Start-SoloRaid.ps1 -Smoke

# 전원 봇: 기믹 진입 후 봇 대기로 실패 → 재시작 → 정상 참여 승리
.\Scripts\Start-SoloRaid.ps1 -Scenario Mechanic

# 사람 자리에는 자동 입력 없이 봇 세 명으로 같은 순서 확인
.\Scripts\Start-SoloRaid.ps1 -Scenario HumanMechanic
```

`-RenderLeader`는 전원 봇 검사에서도 첫 게임 화면을 띄운다. `-DurationSeconds 30`은 사람 창을 띄우고 준비 후 자동 전투·30초 후 종료한다. 사람의 입력은 생성하지 않는다. 자동 검사 성공과 실제 사람이 물리 키보드·마우스로 조작한 검증은 구분한다.

`-HeadlessLeader`는 자동 시나리오에서 사람 자리도 화면 없이 실행하는 검사 옵션이다. 사람 자리를 봇으로 바꾸지는 않는다. 일반적인 직접 플레이에서는 생략한다.

게임 내 지휘가 기본이다. PowerShell 창의 F/H/G/S/R/Q를 공격/대기/집결/산개/재시작/종료의 대체 조작으로 사용할 수도 있다.

기본 엔진은 `D:\UE_5.8`, 포트 `18842`, 최대 FPS `30`, 프로세스별 준비 대기 `600초`다. `-EngineRoot`, `-Port`, `-MaxFPS`, `-StartupTimeoutSeconds`로 조절한다. 기존 포트 사용 프로세스를 종료하지 않는다. 첫 화면 준비는 수 분 걸릴 수 있다. 설치 엔진 캐시는 읽기 전용으로 사용하며 자기 임시 캐시만 생성한다.

`Saved/SoloRaid/<실행 ID>/Result.json`과 역할별 작은 로그를 남긴다. 종료 시 자기 프로세스, UserDir, 캐시, 중복 로그를 정리한다. 원본 Binaries/Intermediate/DDC 및 다른 실행은 정리 대상이 아니다. 강제 터미널 종료로 finally가 실행되지 않았으면 해당 실행 ID의 소유권을 확인해 정리한다.

## 검증 기록

기존 `12becc78`은 4클라이언트 공격·대기·산개·재시작과 D3D12 화면까지 확인한 구현이다. 당시 소환 기믹 완주와 실제 사람 조작은 검증하지 않았다. 근거는 `Saved/BuildChecks/SoloRaid-20261115/`에 있다.

2026-11-16 정상 Editor 최종 빌드·링크가 통과했다. 보스 실행기 소유권/기존 프로필 검사 6개(기존 예상 거절 경고 1건)와 명령·위험 범위 검사 2개가 통과했다. 실제 사람 자리(Bot=-1)+봇 3명에서 소환 2마리의 원래 HP·30초 제한을 유지한 실패→재시작→정상 공격 처치→다음 페이즈→승리를 반복 확인했다. 최종 DLL 8A66562F에서는 참가자 네 Pawn 교체·장비/입력 준비·사람 패널 입력 잠금 복구 후 클리어를 화면 없는 실행으로 확인했다.

D3D12 화면에서 패널, 소환, 실패·승리를 직접 캡처했다. 합성 키·마우스 입력으로 패널 명령/봇별 대기·기믹 무시/집결·산개/주인공 이동/잠금 복원/재시작을 확인했다. 실제 사람이 물리 키보드·마우스로 끝까지 플레이한 검증은 아니다. 보스·소환몹 HP나 기믹 완료 상태를 주입하지 않았다. 자기 임시 산출물 약 1.129GiB를 정리했고, 작은 결과와 최종 캡처는 `Saved/BuildChecks/SoloRaidPlayable-20261115/Completion.json` 및 해당 실행 ID에 남겼다. 초기 컴파일·접속 실패와 최종 성공은 구분해 기록했다.

기존 `RPGRidingRegistrationTests.cpp`와 `RPGRidingRegistrationUiTests.cpp`의 `FRidingRegistrationFailures` 중복 보정은 로컬 테스트 클래스 이름 변경으로 보존한다. 테스트 전용 게시 예외에 따라 이 기능 커밋에는 포함하지 않는다. 원격 소스만 새로 체크아웃한 빌드에는 해당 기존 이름 충돌 정리가 별도로 필요하다.
