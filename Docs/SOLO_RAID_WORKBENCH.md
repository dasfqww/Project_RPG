# 혼자 사용하는 로컬 레이드 테스트

프로젝트 루트의 PowerShell에서 실행한다.

```powershell
.\Scripts\Start-SoloRaid.ps1
```

기본값은 **내가 조작하는 게임 창 하나 + 자동 조작 클라이언트 세 개 + 전용 서버 하나**다. 서버와 보조 클라이언트는 숨겨서 실행한다. 모든 캐릭터는 실제 네트워크 플레이어이며 서버의 이동·GAS 피해 판정을 사용한다. Steam, 백엔드, 다른 계정은 필요 없다.

```powershell
# 더 가볍게: 나 + 보조 캐릭터 한 명
.\Scripts\Start-SoloRaid.ps1 -Players 2

# 보조 캐릭터의 화면도 관찰
.\Scripts\Start-SoloRaid.ps1 -Players 4 -ShowBots
```

게임 창에서는 평소처럼 내 캐릭터를 조작한다. 실행한 **PowerShell 창을 선택한 뒤** 다음 키로 보조 캐릭터를 지시한다.

| 키 | 동작 |
|---|---|
| F | 보스에게 접근해서 기본 공격 반복 |
| H | 보조 캐릭터 이동·공격 중단. 보스는 계속 공격하므로 실패 상황 관찰 가능 |
| S | 보스 주변 약 6m의 각자 다른 방향으로 이동. 자동 공격 중단 |
| R | 현재 전투를 실패 처리하고 기존 레이드 재시작 경로로 보스·참가자 복구. 준비 상태에서 F로 재개 |
| Q | 이 실행이 만든 서버·클라이언트 종료 및 임시 데이터 정리 |

시작할 때 모든 클라이언트의 무기·입력 매핑 준비를 기다린다. 준비 중 보스 AI는 멈추며 **F를 눌러야 전투를 진행한다**. 재시작도 준비 상태로 돌아간다. 전투 제한 시간은 이 개발 세션에서만 30분이다.

## 범위

- `/Game/Maps/bossmap`의 현재 콘텐츠를 사용한다. 원본 맵·보스 에셋·밸런스는 저장하거나 수정하지 않는다.
- 빈 개발용 장비 상태에 대검을 메모리로 지급한다. 기존 장비를 덮어쓰거나 실제 인벤토리·보상을 저장하지 않는다.
- 자동 캐릭터는 Enhanced Input의 이동·기본 공격을 사용한다. 보스 HP 감소·직접 스킬 활성화로 공격 성공을 대신하지 않는다.
- 현재 보조 행동은 접근·기본 공격·대기·산개다. 장애물 길찾기, 자동 회피, 소환 기믹 해결, 힐러·탱커 역할 판단은 지원하지 않는다. 산개는 기믹의 정답 판정이 아닌 재현용 배치다.
- 실제 로그인·파티 초대·입장권·백엔드 정산·Steam·다중 PC 검사는 별도다. 여기서 전투가 성공해도 해당 흐름의 성공을 뜻하지 않는다.
- 일반 실행과 Shipping에서는 켜지지 않는다. 명시적 개발 플래그 두 개와 `Saved/SoloRaid` 내부 제어 파일이 필요하며 백엔드 던전 자격이 남아 있으면 거절한다. 실행기는 루프백에만 서버를 바인딩한다.

## 실행과 진단

정상 `Project_RPGEditor` 빌드가 필요하다. 오래된 DLL이면 실행기가 클라이언트를 만들기 전에 안내한다. 기본 엔진 위치는 `D:\UE_5.8`, 포트는 `18842`, 최대 FPS는 `30`이다. `-EngineRoot`, `-Port`, `-MaxFPS`로 바꿀 수 있다. 같은 포트의 기존 프로세스는 종료하지 않는다. 첫 화면은 에셋·셰이더 준비로 수 분 걸릴 수 있으며, 기본 준비 대기 한도는 300초다(`-StartupTimeoutSeconds`). 설치된 엔진 pak/파일 캐시는 읽기 전용으로 활용하고 새 임시 캐시만 해당 실행 경로에 만든다.

`Saved/SoloRaid/<실행 ID>/Result.json`과 역할별 작은 로그를 남긴다. 종료 시 해당 실행이 만든 프로세스, UserDir, 캐시, 중복 로그를 정리한다. 원본 Binaries/Intermediate/DDC 및 다른 실행은 정리 대상이 아니다. 강제 터미널 종료로 finally가 실행되지 않았다면 그 실행 ID의 프로세스·폴더 소유권을 확인한 뒤 정리한다.

자동 확인 모드는 사람 자리도 자동 입력으로 바꾸며 모든 창을 숨긴다.

```powershell
.\Scripts\Start-SoloRaid.ps1 -Players 4 -Smoke

# 같은 검사를 첫 번째 캐릭터의 실제 게임 화면과 함께 확인
.\Scripts\Start-SoloRaid.ps1 -Players 4 -Smoke -RenderLeader
```

실제 사용에서 보이는 화면과 물리 입력의 확인은 자동 모드와 구분한다.

`-DurationSeconds 30`을 지정하면 화면이 있는 일반 세션에서 준비 후 자동 전투·30초 뒤 자동 종료한다. 이 경우 콘솔 키 입력은 받지 않으며 사람 캐릭터의 입력은 자동화하지 않는다.

## 2026-11-15 확인 범위

정상 Editor 전체 빌드/링크와 전용 서버·실제 클라이언트 4개의 접속·장비/입력 준비를 확인했다. 기본 입력 공격으로 서버 보스 HP 300→186, 대기/산개 전환, 네 캐릭터 모두 각 산개 목표의 50cm 이내 도착, 기존 실패→재시작 경로를 통한 HP 300 복구와 재공격을 확인했다. D3D12 게임 창·HUD·기믹 실패 결과 화면을 직접 캡처해 확인했다. 물리 키보드/마우스 입력, 기믹 완주, 저장/Steam 검증은 아니다.

빌드 과정에서 기존 `RPGRidingRegistrationTests.cpp`와 `RPGRidingRegistrationUiTests.cpp`의 `FRidingRegistrationFailures` 이름 중복으로 링크가 실패했다. UI 검사 클래스 이름 두 곳을 `FRidingRegistrationUiFailures`로 구분한 **로컬 검증 수정**을 유지한다. 테스트 전용 게시 제외 지침에 따라 이 수정은 레이드 기능 커밋에 포함하지 않는다. 따라서 원격 소스만 새로 체크아웃한 빌드에는 이 기존 중복 이름 문제의 별도 정리가 필요하다.

작은 실행 근거는 `Saved/BuildChecks/SoloRaid-20261115/` 및 해당 요약이 가리키는 `Saved/SoloRaid/<실행 ID>/`에 남긴다. 준비 경로 판정·PowerShell 파일 교체/실시간 로그 공유 읽기·렌더 캐시 설정의 초기 실패/중단은 최종 통과와 구분해서 기록한다.
