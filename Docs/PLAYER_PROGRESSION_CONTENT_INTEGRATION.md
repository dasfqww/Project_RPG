# 첫 성장 구간 콘텐츠 연결과 다음 구현

확인일: 2026-10-29  
상태: **실제 호출 코드를 대조한 구현 준비 문서. 콘텐츠 등록·기능 구현 완료를 뜻하지 않는다.**

[첫 구간 수치안](PLAYER_PROGRESSION_FIRST_SLICE_V01.md)의 훈련 → A1 → A2 → A3 → 일반/고난도 보스를 기존 온라인 흐름에 연결한다. 경험치·SP·해금은 [영속 성장 API](../Backend/CHARACTER_PROGRESSION_API.md)의 기존 규칙을 사용한다. 이번 작업에서는 문서만 수정했으며 다른 담당자의 스킬·HUD·입장·아이템 구현과 검증 입력을 변경하지 않았다.

## 1. 이미 있는 것과 아직 연결할 것

| 경계 | 현재 코드/설정 | 남은 연결 |
|---|---|---|
| 성장 판정 | `FirstSliceProgression`에 콘텐츠 ID·선행 플래그·경험치 100·해금 구현 | 실제 완료 정산이 정확한 콘텐츠 ID/난이도/버전으로 생성돼야 함 |
| 백엔드 선택/할당 | `DungeonContentCatalog`가 허용 ID·난이도를 실제 맵 패키지에 매핑 | 기본 `appsettings.json`에는 현재 `Dungeon.RaidSwordMan`만 등록됨 |
| 로비 목록 | `URPGDungeonDefinition`과 로비의 `DungeonDefinitions` 목록 | 첫 구간의 정의 5개와 목록 참조가 필요. 파일 생성만으로 목록에 추가되지 않음 |
| 서버 수락 | `URPGDungeonServerDefinition::BuildAssignedSelection`이 ID·실제 맵·난이도·보상을 검사 | 첫 구간 서버 정의와 해당 GameMode의 `DungeonServerDefinitions` 참조가 필요 |
| 완료 보고 | GameMode가 입장 확인 때 확정한 보상 사본을 `ReportConfiguredDungeonClear`에서 사용 | 훈련/입문 목표의 서버 완료 판정과 보고 연결 필요 |
| 지급/성장 | 완료·수령 자격이 있는 정산을 성장 조회 등이 반영 | 훈련의 경험치 전용 완료 경로와 첫 구간 재료·개인별 추첨 연결 필요 |

현재 소스 대조 근거는 [성장 규칙](../Backend/ProjectRpg.Backend/Domain/CharacterProgression.cs), [할당 카탈로그](../Backend/ProjectRpg.Backend/Application/DungeonContentCatalog.cs), [기본 서버 설정](../Backend/ProjectRpg.Backend/appsettings.json), [로비 목록 로드](../Source/Project_RPG/Private/UI/Lobby/RPGOnlineLobbyDungeonSelection.cpp), [서버 정의](../Source/Project_RPG/Private/Online/RPGDungeonServerDefinition.cpp), [완료 보고](../Source/Project_RPG/Private/GameMode/RPGGameModeBase.cpp), [보상 작성 규칙](../Source/Project_RPG/Private/Economy/RPGDungeonRewardDefinition.cpp)이다. 에셋 내부를 이번에 재조회하거나 실제 게임을 실행하지 않았다.

## 2. 등록 단위

프로필은 `FirstSlice.GreatSword.v1`, 성장 지급에 필요한 보상 버전은 정확히 `FirstSlice.v1`이다. 다음 5개 ID·6개 난이도 조합을 같은 의미로 연결한다.

| 콘텐츠 ID | 난이도 | 선행 플래그 | 완료 시 추가 비트 | 기본 성공 경로의 누적 경험치/레벨/SP | 해금 |
|---|---|---:|---:|---|---|
| `Progression.Training` | Normal | 0 | 1 | 100 / 2 / 3 | 회전 베기·투지 해방 |
| `Progression.Intro1` | Normal | 1 | 2 | 200 / 3 / 6 | 도약 강타 |
| `Progression.Intro2` | Normal | 3 | 4 | 300 / 4 / 9 | A3 진입 |
| `Progression.Intro3` | Normal | 7 | 8 | 400 / 5 / 12 | 일반 보스 진입 |
| `Progression.FirstBoss` | Normal | 15 | 16 | 첫 일반 완료 500 / 6 / 14 | 고난도 진입 |
| `Progression.FirstBoss` | Hard | 31 | 32 | 일반 첫 완료 직후라면 600 / 7 / 15 | 고난도 완료 기록 |

수치는 선행 콘텐츠를 한 번씩 끝낸 예시다. 기존 규칙은 새 세션의 반복 성공에도 경험치를 주며 900에서 멈춘다. 경험치를 먼저 쌓아도 선행 플래그를 건너뛰지 않는다. 완료 비트를 이미 받았어도 새 세션의 성공 보상은 별개다.

서버/로비 정의는 ID마다 하나씩 두고, 보스 정의 한 개에서 Normal·Hard를 제공할 수 있다. 다른 구간에는 Easy·Hard·Hell을 임의로 추가하지 않는다. 로비 정의의 기본 난이도는 허용 목록에 포함된 Normal로 지정해야 한다. 현재 클래스 기본값 Hard를 그대로 복사하면 Normal 전용 정의가 검증에 실패한다.

A1~A3는 서로 다른 학습 목표이며 같은 공간을 재사용할 수 있다. 현재 서버 카탈로그는 ID 중복을 거절하지만 서로 다른 ID의 같은 맵 사용을 금지하지 않는다. 따라서 새 맵 세 개를 필수로 만들 필요는 없다. 같은 맵을 쓰면 인증된 ID에 따라 과제를 선택하는 서버 연결이 별도로 필요하다. 현재 GameMode에 그 과제 분기가 있다고 가정하지 않는다. 최종 맵 패키지는 아직 정하지 않았다.

## 3. 구현 전에 해결할 구체적인 공백

### 3.1 경험치만 주는 훈련 완료

수치안의 훈련 보상은 경험치 100이며 재화·아이템은 없다. 착수 전에는 `URPGDungeonRewardDefinition::BuildSettlement`가 재화/아이템이 모두 비면 거절해, 서버 정의에서도 빈 보상과 `FirstSlice.v1`을 사용할 수 없었다. 아래 후속은 이 UE 정의 경계의 해결 범위다.

또한 `bGiveReward=false`인 기존 완료 경로는 `ReportDungeonFinished(true)` → `ReportDungeonClearedWithRewards("no_reward", [], [])`다. 성장은 정확한 `FirstSlice.v1`만 인정하므로 이 경로의 완료를 훈련 경험치 지급으로 사용할 수 없다.

백엔드의 현재 `settle-rewards` 엔드포인트는 빈 `Changes` 배열을 개수 검사에서 거절하지 않으며, 정산 Worker는 재화/아이템이 있을 때만 각각 지급 명령을 만든다. 따라서 우선 확인된 공백은 UE 작성 규칙과 버전 연결이다. 이것을 경험치 전용 정산의 실제 저장/완료 검증으로 일반화하지 않는다.

2026-10-29 후속으로 기존 보상 버전 `FirstSlice.v1`을 명시적 opt-in으로 사용해 빈 payload를 만들고 기존 서버 배정 선택에 복사하는 UE 경계를 구현했다. 일반 빈 보상/다른 버전과 맵·난이도 오류는 계속 거절하며 가짜 골드·새 API/플래그는 없다. 다른 담당의 공통 GameMode·backend·에셋을 유지한 분리 CL/DLL/native 5개가 통과했다. [작성 조건과 검증 범위](DUNGEON_REWARD_INVENTORY_FIRST.md#경험치-전용-완료의-작성-경계-2026-10-29)를 따른다. 4절 1단계 전체의 실제 훈련 성공/정산 검증 완료는 아니며, 다음은 실제 목표/보상 에셋·카탈로그 연결과 완료 경로 실행이다.

같은 날 실제 `DA_DungeonReward_ProgressionTraining`을 `FirstSlice.v1`/빈 재화·아이템으로 저장하고 새 프로세스에서 재로드했다. 작성 1개·반복/재로드 저장 0, Valid/오류·경고 없음·dirty=false와 동일 해시를 확인했다. 성공 검증이 NotValidated를 반환하던 보상 C++도 Valid로 보완하고 강화한 native 5개를 통과했다. [실제 에셋/근거](DUNGEON_REWARD_INVENTORY_FIRST.md#훈련-경험치-전용-보상-에셋-저장-2026-10-29)를 따른다. 목표 컴포넌트·맵/GameMode·서버 정의 참조와 정산의 연결, 정상 공유 모듈 적용은 아직 별도다.

### 3.2 훈련 중 고유 능력 사용과 해금 순서

처음에는 돌진·차지만 습득하고, 회전·투지 해방은 훈련 완료 후 해금된다. 따라서 훈련 완료 전에 투지 해방 사용 성공을 필수 조건으로 두면 완료할 수 없다. 도약도 A1 완료 후 해금되므로 A1의 필수 조건으로 삼을 수 없다.

훈련의 필수 실습은 현재 습득한 기본 공격·회피·돌진·차지로 구성하고, 회전·고유 능력의 실제 사용 실습은 해금 후 단계로 배치하는 안을 우선한다. 완료 전에는 고유 능력의 설명/시연만 제공할 수 있다. 저장되지 않은 임시 습득이나 개발 초기화로 잠금을 우회하지 않는다. 필수 적중 횟수·실패 조건·개인/파티별 달성 판정은 콘텐츠 구현 전에 구체화해야 한다.

### 3.3 확정 재료와 개인별 장비 추첨

현재 `URPGDungeonRewardDefinition`과 정산 모델은 파티 수령자에게 지급할 공통 재화·아이템 묶음을 표현한다. 첫 구간의 개인별 20% 장비 추첨, 추첨 내 4종 균등 분배, 계정 최초 외형을 이 배열에 적는 것만으로 구현할 수 없다.

확정 재료는 훈련 0, 입문 광석 2, 보스 광석 4/증표 2다. 광석·증표의 실제 저장 식별자와 장비 Definition/귀속·버전을 아이템 담당과 맞춘 뒤 작성한다. 경험치·SP를 지갑 재화로 대신 저장하지 않는다. 개인별 추첨을 연결할 때는 최초 확정 결과가 재시도에서 유지되고, 정산 수령 자격·가방 우선/초과 우편·중복 지급 방지가 기존 경로에 남아 있어야 한다. 제작·강화·분해·이전은 별도 단계다.

### 3.4 수신 완료와 실제 과제 성공

기여 수신기의 100단위 완료와 HUD 표시는 과제 성공 또는 보스 그로기/파괴 반응의 구현을 뜻하지 않는다. A3를 무력화 실습으로 만들 때는 승인된 서버 상태를 어떤 목표에 연결할지 정하고, 반복 과제/새 시도의 표적 초기화와 이전 시도의 늦은 이벤트를 구분해야 한다. 다른 담당자의 수신기/HUD 검증을 이 콘텐츠 완료 근거로 사용하지 않는다.

## 4. 다음 구현의 순서와 수정 경계

| 순서 | 최소 결과물 | 착수할 경로/자원 | 완료 기준 |
|---|---|---|---|
| 1 | 훈련의 경험치 전용 정산 | `Economy/RPGDungeonRewardDefinition.*`와 필요시 GameMode 완료 보고·관련 기존 검사. 공통 파일은 담당 종료/인계 후 예약 | 무관한 빈 보상은 계속 거절. 훈련 성공이 정확한 버전의 완료 정산으로 남고 기존 성장 반영 경로에 도달 |
| 2 | 훈련 목표/서버 완료 | 전용 콘텐츠 경로의 새 과제 구현·맵/Definition. 기존 스킬/Controller에 과제 분기를 넣지 않음 | 잠긴 스킬 사용을 요구하지 않고 서버가 목표 완료·이번 시도의 자격을 확인해 한 번 보고 |
| 3 | 첫 콘텐츠 공개 | 신규 로비/서버/보상 에셋, 해당 GameMode 참조, `Config/DefaultGame.ini` 목록, backend 콘텐츠 설정을 함께 조율 | 로비 선택 → 같은 ID의 서버 할당 → 실제 맵·난이도 수락이 일치. 구현 안 된 후속 과제는 공개하지 않음 |
| 4 | A1 → A2 → A3 | 3개 ID와 서로 다른 접근/공격 기회/기여 목표, 입문 재료 정의 | 각 해금 이전 스킬로 완료 가능. 순차 플래그와 재시도 자원 정책 연결 |
| 5 | 일반/고난도 보스 | 기존 보스/아이템 담당의 정의·반응·개인 보상 연결 | 일반 완료 후 고난도 해금. 개인 추첨/최초 외형·재료 지급이 확정 정책대로 동작 |

위 경로는 다음 착수 후보이며 이번 예약 범위가 아니다. 매 단계 시작 전에 로드맵 12절의 최신 예약과 실제 호출 코드를 다시 확인한다. 공통 GameMode/Config/backend 설정을 다른 담당과 동시에 편집하지 않는다. 단순 Asset Manager 스캔 등록과 실제 로비 목록·GameMode 참조 연결도 구분한다.

## 5. 이후 확인할 결과

이번에는 문서 참조와 코드 대조만 수행했다. 아래는 구현 후 확인할 조건이며 실행 성공 기록이 아니다.

- 새 캐릭터의 실제 훈련 성공에서 경험치 100·레벨 2·3 SP·회전/고유 능력 해금이 저장된다. 새 스킬을 빈 슬롯에 자동 편성하지 않는 기존 정책을 유지한다.
- 같은 완료 기록을 다시 조회/전송해도 경험치가 중복 증가하지 않는다. 실패·중도 이탈·보상 미대상·미완료 정산은 지급 근거가 되지 않는다.
- A1 완료 후 도약이 해금되고, A2/A3를 건너뛰어 일반 보스에 들어갈 수 없다. 경험치 상한에서도 미획득 완료 플래그를 얻을 수 있다.
- 로비·할당·실제 맵/난이도·정산 버전 중 하나라도 불일치하면 기존 거절/입장 대기 처리를 유지한다.
- 새 전투 시도의 체력/투지/쿨타임/회복약 초기화와 단순 재접속을 구분한다. 이 사건 정책은 아직 연결 대상이며 콘텐츠 등록만으로 완료되지 않는다.

실제 HTTP/DB·멀티플레이·자연 전투 검증은 해당 구현 뒤에 진행한다. 이 문서만을 위해 빌드·게임 실행·새 검증 도구를 추가하지 않는다.
